# 操作循环示意图规范

把角色的核心循环画成「**按键即节点**」的循环示意图,替代纯文字箭头链。评审者一眼看懂"手在做什么、循环长什么形状"。**角色战斗设计稿 / 养成效果稿 / 完整稿三类文档共用本规范**。

> 沉淀自 2026-07 一轮真实角色养成稿评审:文字版循环被要求两轮重画,最终收敛为本规范的键帽 + 双环 + 双入口形态。

---

## 一、什么时候画哪几张(按文档规格)

| 文档规格 | 出图 | 原因 |
|---|---|---|
| **纯战斗设计分稿**(不含养成) | **只出 C0 基础循环** 1 张 | 不含任何养成,画满配循环无意义 |
| **养成效果分稿** | **C0 ＋ 满配(满命/毕业)对照** 2 张 | 养成改变的是节奏,不只是数字——对照图直接展示"买了什么体验" |
| **完整稿**(战斗 + 养成一份到底) | **C0 ＋ 满配对照** 2 张 | 同上,放「操作循环」章 |

**满配图的核心价值**:把养成条目翻译成操作变化(如"恢复 CD 缩短"→"可以卡拍永续维持 Buff")。若满配与 C0 操作节奏无差,说明养成全是纯数值——本身就值得在评审里被看见。

> 🔴 **拓扑先行(反「套模板」铁律)**:画图前先识别该角色循环的**真实拓扑** —— 常见如**跑道型**(攒资源 → 花资源,弹药 / 蓄力角)、**自动环型**(状态自动结算成环,按键只是注入加速,如满层自燃角)、**计量池型**(多渠道注入一个计量资源,按档位走不同出口,如蓄势角)、**双环型**(内圈维持 ＋ 外圈爆发)。同一套键帽语言下,**拓扑必须从角色机制推导,禁止把别的角色的图直接换字** —— 两个角色的循环图若形状雷同,先怀疑画错了。
>
> 本铁律**扩展到所有示意图**(资源流转 / 属性堆叠 / 数值曲线…):图的结构与内容一律从该角色 / 该项目的**具体设计**推导重画,坚决不套皮换字。

## 二、节点与配色(键帽范式)

- **节点 = 按键操作**,键帽样式(圆角矩形 + 描边),标题用等宽字体写按键(`短按 E` / `长按 E` / `A 连段` / `Q` / `闪避 · 弹反` / `点亮头像`…按项目键位约定),副标题一句话效果(≤10 字)。
- **五类语义色**(浅底 + 同族描边 + 深字,示例为冷色系文档主题的参考值,按文档主题调):

| 语义 | 用途 | 参考(浅底 / 描边 / 深字) |
|---|---|---|
| 核心技(蓝) | 特殊技 / 核心资源技 | `#e3ecf9` / `#3f68b0` / `#16305e` |
| 爆发技(金) | 大招 / 爆发窗动作 | `#f7efdc` / `#ba8f2a` / `#6d5310` |
| 填充(灰) | 普攻 / 间隙动作 | `#f1f0ec` / `#9a968a` / `#4a473f` |
| 防御(青) | 闪避 / 弹反 / 格挡 | `#e2f2ec` / `#2e8b6f` / `#0d5c44` |
| 协作(粉) | 协力 / 换人 / 支援 | `#f7e8ee` / `#c26787` / `#7a2f4c` |

- **开始标记必画**:绿色胶囊 `▶ 开始`,指向循环的第一个操作——评审者要知道"从哪里开始按"。
- **箭头双色**:灰 = 常规维持节奏;金(或主题强调色)= 爆发窗时机。图例一行说明。

## 三、双入口:冷启动 / 热启动(有换人 / 支援体系的项目)

满配图区分两种进入循环的方式,各配一个 `▶ 开始`:

- **热启动**:靠体系加速进入(协力入场自带层数 / 能量、换人继承 Buff 等)——循环直接进入巡航段;
- **冷启动**:无外援站场自起——标注从零到巡航要几个操作、几秒(如"连发 2~3 枚,约 2.5s 叠到阈值")。

冷启是最容易被漏画的一条:开场第一个上场、或队友没转起来时,玩家走的就是冷启路径。

---

## 四、双环结构(维持 + 爆发型循环)

凡是「平时维持状态、窗口期倾泻」型角色,满配图画成**内外双环**:

```
[▶ 热启] → 入场节点 ─┐          ┌→ [爆发节点1] (同列直下)
[▶ 冷启] → 自起节点 ─┴→ ┌────────┐ │      ↓
                        │ 内圈维持环 │─窗口开→ [爆发节点2]
                        │ (虚线框)  │ ↑      ↓
                        └────────┘ └─ 回内圈 ←┘
```

- **内圈** = 维持环(虚线框包住,框上写目标,如「Buff 一直不掉」),3 节点内可三角形排布(更好看);
- **外圈** = 爆发列,节点**同列直下**,窗口触发用金色箭头水平引出;
- **维持工具箱**:内圈把"达成同一目标的多条渠道"逐行列出(卡拍 / 防御回弹 / 装填兜底 / 大招重置…),每行以对应键帽开头——设计语义是"玩家用哪条都被奖励,技巧高的用得省、技巧低的用得稳"。

**卡拍范式**(顺带的设计手法):把"资源恢复 CD"与"Buff 持续时长"设为同拍(如都 5s),极限玩家可精准卡拍零净耗永续——这是把 QoL 变成技巧表达的锚点,循环图上要把这个节拍标出来。

---

## 五、排版铁律

1. **网格对齐**:节点按列 / 行网格摆放,同列直上直下、同行水平直连;
2. **线少弯折**:箭头只走横平竖直,全图 90° 转角控制在 1~2 处;
3. **标签不遮挡**:箭头标签放进无节点的"车道"(间隙加宽让位),长说明统一下沉到图内脚注区;
4. **美观优先**:以上是默认解,不是教条——若不对齐或其他排布明显更好看(如 3 节点小环的三角形),直接用,好看是最终裁判;
5. **落图形式**:内嵌 SVG(离线归档),配色贴文档主题;`viewBox` 放大到 700~800 宽不心疼——审阅 HTML 有图表 lightbox,大图更清晰。

---

## 六、自检

- [ ] 有 `▶ 开始` 标记(满配图冷 / 热双入口)
- [ ] 节点全是"按键 / 操作",效果只做副标题或箭头标签
- [ ] 满配图能看出"养成买到的操作变化"(节奏差异标强调色)
- [ ] 无文字压块;转角 ≤2;图例齐(色 = 语义,箭头 = 节奏 / 窗口)
- [ ] 纯战斗设计分稿只有 C0 图
- [ ] 拓扑由该角色机制推导(与他角循环图形状雷同时,说得出机制上的理由)
