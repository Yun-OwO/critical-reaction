# 效果与养成设计文档范式

给一个**已有基础设计**（动作 / 招式 / 核心机制）的角色，单独展开「**效果 + 养成 + 数值**」这一层时，用这套结构产出一份**审阅级 HTML**。

> **适用**：gacha / 抽卡品类（含命座 / 养成物 / 属性词条）。买断 / 非 gacha 项目取适用子集（技能附带效果 + 属性投放 + 数值验证），跳过命座 / 养成物章。
>
> **跟角色主设计稿的分工**：基础动作 / 招式 / 资源清单在角色主设计稿；本范式只管「效果挂什么、养成解锁什么、词条怎么堆、数值健不健康」。

---

## 一、文档结构（7 章 · 按阅读顺序排）

| 章 | 内容 | 适用 |
|---|---|---|
| 壹 设计说明 · 核心循环 | 角色定位 / 本稿范围 + **操作循环示意图（C0 ＋ 满配对照两张）**，见 [operation-loop-diagram.md](operation-loop-diagram.md) | 通用 |
| 贰 技能附带效果 | 每招挂的 buff / debuff / 标记 / 状态（招式 → 效果表） | 通用 |
| 叁 命座 / 养成解锁效果 | 按付费哲学（C0 完整 / 拐点 / 鲸鱼收官），每段解锁 / 强化一个效果 | gacha |
| 肆 养成物套装效果 | 2 / 4 件套，4 件套 = 流派核心 | gacha |
| 伍 属性投放与堆叠审计 | 投放表 + 词条优先级 + **堆叠审计五件套**（见 § 三）+ 资源经济 | 通用 |
| 陆 数值建模验证 + 边际效应 | 养成梯度建模（图）+ **连点里程碑** + 边际分析 + 健康自检 | 通用 |
| 柒 最终总结 | 效果 / 养成 / 数值三层闭环 + 待办（如 PVP 复核） | 通用 |

> 🔴 **阅读顺序铁律**：属性投放章必须排在**技能附带效果与命座 / 养成物之后** —— 它汇总的正是前两处投向各属性的条目，先读投放再读来源会来回翻。循环图放最前（壹），先让评审知道"手在做什么"，再看往这双手上挂什么。

## 二、图示（5 类）

每个有梯度 / 张力 / 流程的地方配一张图，胜过纯文字表：

1. **操作循环示意图（C0 ＋ 满配对照）** —— 按键即节点的键帽循环图，满配图展示"养成买到的操作变化"；规范细则（键帽 / 开始标记 / 冷热启动 / 双环 / 排版铁律）见 [operation-loop-diagram.md](operation-loop-diagram.md)。
2. **养成曲线** —— 命座 C0→C6 累计强度指数 **SVG 折线** + 健康区带 + 质变跳点高亮。
3. **逐级边际** —— 每级边际增益柱状图。**形态按你项目的付费哲学定**，以下只是示例 / 推荐：业界 gacha 常见「拐点 + 收官」**双峰**（如 C2 / C6，分水岭 + 鲸鱼勋章），并非必须逐级严格递增；通用的风险提示是单段过陡（>35~40%，接近"半个新角色"）会有「X 命起玩」舆论风险，应削缓。
4. **连点里程碑** —— 按**你项目玩家的实际购买节奏**画累计增益柱状图（怎么分包由项目商业化设计定；「1+2 连点、3+4 连点、直奔收官」只是常见 gacha 示例），每个"连点包"标注主题（这一包买到什么体验）+ 同轴检查（包内 / 跨包的同属性叠加是否有界）。呈现两处：**养成 / 命座章**配「连点节奏表」（连点包 / 主题 / 累计增益 / 同轴检查），**数值章**配里程碑柱状图 —— 两处都注明「包划分按项目商业化定、此处为示例口径」。
5. **属性极限堆叠横条**（审阅 HTML 版为五件套必备件 ②，见 § 三）—— 每条属性一行横向堆叠条，分段按来源着色（技能效果 / 被动 / 命座 / 套装 / 面板词条 / 窗口·换算类），条尾标极限值、窗口型注明。来源 ≤2 的线同样画：分段少不影响读图，缺图才是缺件。

> 图用内嵌 SVG（离线归档），配色贴文档主题；对话内可先用可视化工具做即时仪表盘给策划看，再固化成 SVG。**「📐 三问注解框」的摆放：有卡片承载的必须放进卡片内**（SVG → ▲ 图注 → 注解框，同卡成一个视觉单元，含堆叠横条这类带卡审计图）；无卡片承载的（如表格之后）独立成块即可。

## 三、属性堆叠审计（极限同刻视角）

命座是玩家花钱抽的 —— **同一属性跨来源（技能效果 ＋ 被动 ＋ 命座 ＋ 套装）叠加的总量与分布必须显式审计**，不能只看单条文案。写法：

1. **逐属性列极限构成**：把投向同一属性的所有条目同刻叠满取最坏情况（如「精通：机制层满 +30% ‖ C4 +30% ‖ 被动转化 ≈+15% → 极限 ≈+75%」），窗口型收益单独标注（非常驻）。
2. **逐属性给判定**：✅ / ⚠️，⚠️ 必须写清兜底机制。常见兜底四类：**转化上限**（如"被动转化 30% 封顶，极限堆叠时恰好触顶 = 天然调节阀"）、**幂函数 / 软衰减换算**、**行为限幅**（施放动画上限 / 容量上限 / 层数封顶）、**单向阀**（资源只出不返）、**窗口时限**（窗口型收益时长封顶、与常驻分桶）。兜底条数按实际设计来：**有几条写几条**（别硬凑「四道」）；软性行为代价（如蓄层减速）是操作张力不是硬阀，不计入；确实没有兜底就明说并直接给结论。
3. **收束一句整体判定**：概括分布形态（如「一高五稳」「单轨集中」），点名唯一要交数值确认的项。只写有价值的总结性语句，不堆废话；**审阅 HTML 版必须用醒目条呈现**（`.philosophy` 大字块收尾），不许淹在小字备注里。
4. **极限单发校验**：所有窗口（爆发窗 ＋ 易伤窗 ＋ 满层）同刻叠满的单次伤害 ≈ 平时的几倍 —— 有界（~1.3× 量级）才健康，出现爆炸组合（数倍）说明窗口没分桶。口径必须**同招对比**：极限窗口内的一发 vs 无窗口的平时同一招 —— 别拿机制设计倍率（如资源层数梯度）冒充堆叠极限值。

**审阅 HTML 版呈现「五件套」（顺序固定）**：① 投放表（谁吃到 × 属性 × 来源与量）→ ② 极限堆叠 · 来源构成横条图（分段按来源着色：机制 / 命座 / 套装 / 面板词条，条尾标极限合计、窗口型注明）→ ③ 📐 三问注解框（**分行式**：标题行「📐 主题 · 怎么算 · 为什么 · 结果」＋ 每问单独一行带关键词标签 —— 审阅 HTML 用 `.anno-box`，别糊成一段小字。**怎么算**＝同刻叠满取最坏的口径；**为什么**＝该角色的具体审计动机，别写通用套话；**结果**＝几绿几黄、最高位是谁、有无爆炸组合）→ ④ 极限同刻判定表（逐线极限构成算式 ＋ 判定）→ ⑤ 兜底机制清单 ＋ 整体判定醒目条。兜底机制必须从该角色真实机制里提取（类别见第 2 条，有几条写几条），设计里确实没有就不硬编；样板见烬羽稿柒章 ／ 苍岚养成稿伍章。

**审计时常见踩坑**（沉淀自真实评审迭代）：
- **同轴撞车**：复合属性（如"精通"本身换算出效率与伤害）与其子轴（"效率%"）在相邻命座各投一次 = 双重投放，删一留一；
- **定位越界**：副 C / 辅助的命座别开主 C 的核心词条面（如暴击伤害）—— 配装信号分裂 + 抢生态位，是"国民老婆"前兆；数值 rider 应回流角色自身的转化引擎；
- **入口过多**：弹药 / 层数类资源的获取入口（基础恢复 / 防御操作 / 命座回费 / 大招重置…）要逐一数——新命座别再开第 N 个同类入口，改投别的轴；
- **永续漏洞**：「大招后接技能刷新持续时间」这类组合会让限时 Buff 事实永续——每条"叠满 / 不衰减"文案都要过一遍组合自检；
- **演出冲突**：大招演出期间自动追加发射物 / 特效会被大招画面淹没，玩家感知不到——改成时序错开或走 UI / 数字反馈。

## 四、数值注解四要素（每个数值点配小字）

凡是出现「算出来的数」（命座梯度 / 倍率 / 边际 / 词条比），旁边小字配齐**四要素**，缺一不可：

| 要素 | 写什么 |
|---|---|
| **怎么算** | 公式 / 方法（如：每命座效果折算 DPS%，在 C0 = 100 上累乘） |
| **为什么这么算** | 设计意图（如：C2 / C6 做付费 / 鲸鱼跳点） |
| **算的过程** ⭐ | **实际演算步骤**，别只给结论（如：C1 +5% → 105；C2 +12% → 118；… C6 +37% → 195） |
| **结果** | 结论 + 是否越界（如：195 ÷ 100 = +95%，落健康区） |

> 「算的过程」最容易漏 —— 评审要能**复算**，不能只看到结论数字。标注基准（如「倍率以 1 势斩势 = 1.0 为准」），避免同一指标多基准打架。

**顺带的养成设计手法 · 卡拍**：把"资源恢复 CD"与"Buff 持续时长"设为**同拍**（如都 5s），极限玩家精准卡拍可零净耗永续维持——这是把 QoL 数值变成技巧表达的锚点；同拍值一旦当作玩法卖点，就要在数值表里锁定，不许后续随手改。
