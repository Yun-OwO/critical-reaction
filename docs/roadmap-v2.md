### 0.1 明日方舟 集成战略（IS）—— 贡献**局内→局外的投资闭环**

IS 是 Roguelite 里少见的、把「攒」本身做成玩法的设计：

| 机制 | 具体规则（来源：prts.wiki / 百度百科 / B站攻略） |
|---|---|
| 三种局内资源 | **源石锭**（通用货币）、**希望**（只用于招募干员）、**目标生命**（生命值） |
| 前瞻性投资 | 诡意行商处可「投资性存款」：**每次存 1 源石锭 → 投资储备余额 +1**，余额**跨探索继承**，上限 **999** |
| 累计投资解锁 | 投资额达到阈值解锁收藏品（如「前瞻性投资系统中累计投资 30 个源石锭」→ 解锁某收藏品） |
| 收藏品 | 单期约 **230 个**（萨米肉鸽/银凇止境），效果各异，是探索途中获得的主要物品，部分有额外解锁条件 |
| 密文板 | 每期若干块，板上条目多为**跨局累计条件**（「在多局游戏中累计胜利 100 场战斗」） |
| 认知塑造 | 永久天赋点，树状解锁 |
| 事件 | 「不期而遇」，选项普遍是**消耗换收益**的结构 |
| 商店 | 诡意行商卖道具和收藏品，可随投资额扩充货架 |

**关键洞察**：IS 的「投资」不是签到奖励，而是**让玩家在局内主动把资源从「这局的战力」换成「跨局的解锁进度」**。这是一个真实的、非最优的抉择——前期存钱会让你这局更弱。这正是我们缺的那块。

### 0.2 Hades —— 贡献**可预期性与门上的信息**

| 机制 | 具体规则 |
|---|---|
| 商店定价 | Charon 商店买神祝福 **150 Obols** 一个（明确的整数锚点，玩家能心算） |
| 稀有度升级点 | **骷髅房**（Skull Chamber）内祝福稀有度提升——把「变强」绑在一种可识别的房间图标上 |
| 门上图标 | 商店、井、金币、花蜜等图标在门框上直接可见，**选门即定价** |
| 局外成长 | 镜夜（Mirror of Night）用黑暗/宝石/钥匙买永久被动 |

**关键洞察**：Hades 的可预期性不靠数值，靠**图标 + 整数锚点 + 升级点固定化**。

### 0.3 colorist（`github.com/1026073226/colorist`）—— 贡献**进化系统的原始形态**

这是个 Minecraft KubeJS 魔法书模组。它的核心代码在 `startup_scripts/lib.js`：

```js
global.MAX_ATTRS = 12;          // 12 个槽位
global.PROG_LENGTH = 18;        // tooltip 里比例条的宽度

// 颜色 → 属性，全是推导，没有一张数值表
global.VALUE_COUNTER = (attr, zero) => {
    // cost  = 0.9 - b/150          蓝越多越省
    // atk   = r^1.1/10 + level^0.8/5   红 → 攻击（非线性，边际递减）
    // hp    = g^1.1/5  + level^0.8/5   绿 → 生命
    // br    = sqrt(brightness) * 2.5 / 100   亮 → 暴击率（开方，更难堆）
    // bd    = darkness / 100               暗 → 暴击伤害
};
```

**关键洞察**：colorist 的装备**没有作者预设的属性**。属性是「你往槽位里混了什么颜色」**实时算出来的**。红染料灌进去攻击涨、绿染料灌进去生命涨、蓝色灌进去消耗降；亮→暴击率、暗→暴击伤害。而且 `level` 是**双资源**——既是强度，也是每次施法扣掉的耐久。

我们本项目已经有 `dyes.ts`（9 种基础染料 + `MIX_TABLE` + `COMPLEMENTARY` 互补色 + `DYE_SLOT_MULTIPLIERS=[1.0, 0.5, 0.25]` 的槽位权重）和 `gameState.dyeSlots`，**化学主题天然就是这个设计的载体**。

## 一、进化系统（源自 colorist）

### 1.1 核心规则

每件装备开放 **1–3 个进化槽**。槽里注入染料，装备的**攻击/耐久/升温等属性由槽内颜色的加权混合实时推导**，而非设计师预设。

颜色通道映射到化学语义（沿用 `colorist` 的 r/g/b→atk/hp/cost 骨架）：

| 通道 | 化学语义 | 推出的属性 | 公式 |
|---|---|---|---|
| **朱赤 r** | 价电子 / 氧化力 | 伤害 | `1 + r^1.1 × 0.35` |
| **碧青 g** | 结构 / 键能 | 生命·护盾 | `1 + g^1.1 × 0.25` |
| **苍蓝 b** | 催化 / 控温 | 放热降低（升温更少=更难过载） | `1 - b × 0.45` |
| **纯度 s** | 反应纯度（色相饱和度） | 暴击率 | `√s × 0.25` |
| **主通道 m** | 主导反应强度 | 暴击伤害 | `1 + m × 0.6` |

混合色沿用项目已有的槽位权重：主槽 1.0 / 副槽 0.5 / 底槽 0.25（`DYE_SLOT_MULTIPLIERS`），
`混合 = Σ(wᵢ × rgbᵢ) / Σ(wᵢ)`——**与 colorist 的 `CALC_ATTRS` 同构**，只是把「等权平均」换成「按槽位权重」。

### 1.1.1 两处对 colorist 的有意偏离（都被单测抓出来过）

**① 「纯度」不能用亮度。** colorist 用 brightness/darkness 做纯度/杂质，但化学上的「纯」指**色相
没被稀释**，不是亮度。改用 HSV 饱和度 `s = (max-min)/max`：互补色混合后亮度不低、饱和度却塌掉，
正是「副反应污染了主反应」。实测红染(#EF4444) 单独饱和度 0.715，红+青(权重 1.0:0.5) 稀释到 0.343。

**② `r^1.1` 是超线性，不是边际递减。** 指数 > 1 意味着**浓度越高、额外收益越陡**——第一版注释
写反了，是单测的数值把它揪出来的。真正的玩法张力来自它和权重的叠加：

- **稀释很贵**：权重是几何级数，任何两槽配置里次色占比都超不过 1/3，主通道会被明显拉平
- **集中很赚**：`^1.1` 超线性，继续往同一个通道堆收益递增

于是每瓶染料都是一次真抉择：**继续往同一通道堆，还是开第二条线**。`√s` 那条则是反向的凹曲线，
暴击率刻意难堆。两条曲线方向相反，玩家不能只认一条。

> 空槽天然是全恒等（`r=g=b=0` → 所有倍率=1），所以推导函数不需要为「没进化」写特判分支。

### 1.2 为什么这套适合我们

- 玩家已有的染色决策（主/副/底槽、互补色抵消）**直接变成装备决策**，不是新系统而是旧系统的纵深
- 染料是稀缺资源，**「这瓶染料给谁」天然是局内抉择**
- 数值全部可推导，新增装备不需要重做数值表

### 1.3 落地切片

- **S1.1（已完成）**：`data/evolution.ts` 纯函数层——`mixEvolutionColor()` / `computeEvolutionStats()` /
  `combineEvolution()` / `describeEvolution()` / `previewInject()`，配 29 条单测。零行为风险，未接入战斗。
- S1.2：装备/武器开放进化槽的存储结构（`ProfileState` + `GameState`，含旧存档 normalize 兜底）
- S1.3：局内「染色工作台」交互（注入/取出染料，接 `previewInject` 做预览）
- S1.4：进化属性接入战斗结算

## 二、局内投资 → 局外（抄 IS 前瞻性投资）

### 2.1 结构

局内引入 **催化券**（in-run currency，与局外的「样本」分开）：

```
局内：战斗掉落 / 宝箱 / 事件选项  →  催化券
      ↓ 诡商（局内商店）：花券买装备、染料、进化材料、祝福
      ↓ 「定向投资」：1 券 → 1 投资储备余额（跨局继承，上限 999）
结算：撤离成功 → 样本（= 局内剩余券 × 系数 + 层数奖励）
      投资储备余额 → 累计投资额 → 跨局解锁（收藏品级永久加成）
```

### 2.2 与 IS 的差异（有意为之）

| | 集成战略 | 临界反应 | 理由 |
|---|---|---|---|
| 投资标的 | 纯解锁进度 | 纯解锁进度 | 保持一致：这是**故意的自我削弱** |
| 结算货币 | 蜡烛/蜡块 + 密文板 | 样本（已有） | 不新增第二套局外货币 |
| 投资上限 | 999 | **120** | 我们单局短，硬上限让人真的能存到 |

### 2.3 累计投资解锁「色谱图鉴」

对标 IS 的**收藏品**（单期 230 个）。我们做 **24 个「谱系」**，解锁条件是**跨局累计**（对标密文板的跨局条目）：

| 档 | 累计投资 | 解锁物 |
|---|---|---|
| Ⅰ | 30 / 60 / 100 | 起始装备、基础染料、常驻被动 |
| Ⅱ | 160 / 240 / 340 | 稀有染料、进化槽 +1、诡商货架 +1 |
| Ⅲ | 480 / 660 / 880 | 传奇谱系、诡商货架 +2、开局携带 1 瓶随机染料 |

> 这些数值是**初稿**，必须实机验证后调。存档格式要能承受改价（见 §六）。

## 三、局内购买（对标 Hades 的整数锚点）

Hades 的商店之所以可预期，是因为**每样东西都是整数金**。我们照抄这个约束：

- 诡商货架 **4 格**，每层重掷
- **所有定价取整到 5 的倍数**，玩家能心算「我还差 15 就够买那个」
- 货架类型按层数推进：L1 只有补给 → L2 出装备 → L3 出染料 → L4+ 出进化材料
- **骷髅房等价物**：每层必出 1 个「提纯台」，本层商店保底出 1 件稀有（对标 Hades 骷髅房提稀有）

## 四、多事件系统

现状：`RoomType` 里已经有 `'event'`，但 `GameScene.ts:1847` 只是 `spawnInstrument()`——**没有任何事件内容**。`src/game/events/EventBus.ts` 只有 20 行 pub/sub。

### 4.1 数据驱动的事件结构

```ts
interface EventDef {
  id: string;
  title: string;
  flavor: string;
  weight: number;                  // 抽取权重
  once?: boolean;                  // 每局一次
  requires?: (ctx) => boolean;     // 前置条件（如「持有 ≥2 件装备」）
  options: EventOption[];
}
interface EventOption {
  label: string;
  hint?: string;                   // 明示代价（对标 IS 的「消耗换收益」）
  cost?: Partial<{ coins: number; ehp: number; temperature: number }>;
  requires?: (ctx) => boolean;
  resolve: (ctx) => EventOutcome;  // 纯函数，便于单测
}
```

**要求**：`resolve` 必须是纯函数（输入 ctx，输出 outcome），这样事件效果可以全部单测，不依赖 Phaser。

### 4.2 首批事件（12 个，覆盖 4 类抉择）

- **纯收益**（免费但稀缺）：修复仪器、+1 价电子上限
- **赌博**：赌 30 券开盲盒（对标 IS 的高风险选项）
- **交易**：用券换染料 / 用染料换券（**这是投资系统的套利口，必须存在但要有价差**）
- **道德抉择**：牺牲一件装备换永久被动（本局）/ 承伤换样本加成

## 五、房间内容丰富

现状 `RoomType` 有 10 种，但多数只有一种实现。扩充方向：

1. **房间变体**：同一 `type` 下多个 `variant`，换地形布局/敌人构成/环境危害（酸雾、低温、静电场）
2. **房间连锁**：`RoomDef.chain` 字段，连打 2 间给叠加奖励（对标 IS 的连续战斗累计经验）
3. **门上奖励预览**（P0-5，已挂起）：把 `chain` 的奖励直接画在门上

## 七、多武器系统（纳入计划）

现状：`weapons.ts` 有 2 把武器（`platinum-knife` 近战 / `reaction-cannon` 远程），
但局内只有 `currentWeapon` 单值。而**既定设计已经假定「玩家每局持有两把」**——
祝福文案是「按当前手持武器分类展示」的，说明双持是原始意图，只是没做完。

计划：
- 局内 `equippedWeapons: [WeaponId, WeaponId]`，可随时切换（不占格）
- 切换有代价（对标 Hades 的「不能同时用两把」）：切换后 **0.8s 硬直**，避免双持变成无脑
- 祝福/进化效果分「双持都生效」与「仅当前手持生效」两档，**沿用现有「按武器分类展示文案」的约定**

## 八、多人联机（只做接入点，不做联机）

**这一节只规划架构接缝，不实现网络。** 一个动作游戏上联机不是「加个 WebSocket」，先把接缝留出来：

| 接缝 | 做法 | 成本 |
|---|---|---|
| **模拟与表现分离** | `GameScene` 里凡是 `Math.random()` 的地方收口到一个 `Rng` 接口，单机用 `Math.random`，联机用「服务器 seed + 帧号」 | 中 |
| **状态快照** | 局内状态能序列化成纯 JSON（`gameState` 已经基本满足） | 小 |
| **输入外置** | 输入已经是 `src/game/input/`，只要保证「输入 → 意图」这一步是纯函数 | 小 |
| **权威判定位置** | 伤害/掉落/撤离结算必须只在「权威端」跑一次，现在这些逻辑散在 `GameScene` 里 | 大 |
| **渲染无关** | 逻辑不直接持有 Phaser 对象引用（现状 `RuntimeEnemy.view` 违反了这一条） | 大 |

**结论**：现在做 1–3（低成本、无行为风险），把 4–5 记成债务。**不要现在动**——
在没有确定性模拟之前接网络，会把现有的单机手感全部打乱。
