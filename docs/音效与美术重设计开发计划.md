### 1.1 用户需求

1. 重新设计音效系统，重新挑选音效；可以从参考项目选择，优先参考何忆卫。

## 2. 当前状态：区分已提交、未接通和草案

### 2.1 代码侧实查

| 模块 | 已有基础 | 尚需完成或核实 |
|---|---|---|
| `src/game/data/sfx.ts` | 语义清单、分类、音量、变体、优先级字段 | 清单声明不等于播放行为已实现 |
| `src/game/utils/AssetLoader.ts` | 从清单取文件，按文件去扩展名注册 audio key | 注册名如 `h_knife`，与播放事件名 `hit-light` 不同 |
| `GameScene.playSfx()` | 设置检查和时间窗节流 | 仍直接 `sound.play(key)`，没有解析语义名到文件 key；没有消费变体、清单音量和优先级 |
| `src/ui/Menu.ts` | 独立 `uiSfx()` | 仍调用 `sfx-ka`、`sfx-liang` 等旧 key，且与战斗播放入口分离 |
| `GameScene.playTone()` | 程序振荡器反馈 | 绕开统一混音/声部预算；由游戏帧触发不等于发生在浏览器真实用户手势中 |
| `SfxLimiter.ts` | 单源冷却、全局间隔、时间窗总量 | `maxVoices=12` 实际是窗口内播放次数，不是真实同时活跃的声部数 |
| `BgmManager.ts` | 单例、跨场景续播、避免立即重复 | 大厅/战斗共用随机曲池；没有按探索、战斗、Boss、撤离分态 |
| 美术 | SVG、程序化场景、电子轨道、共享粒子池 | 同心几何和透明线框占比高；主体材质、动作、空间层次及 UI 不统一 |
| 移动端 | 字号/几何缩放分离、部分尺寸兜底、事件离开按钮 | 此前 20:9 内部分辨率测试不能替代真实手机 CSS 视口、触摸和观感检查 |

**最高优先级不是继续换音文件，而是先修音频入口契约。**

例如：清单的 `hit-light → h_knife.wav` 已存在，但 loader 注册的是 `h_knife`，
播放端直接播放 `hit-light`。文件存在性测试可以通过，实际播放仍可能失败并被空 `catch` 吞掉。

### 2.2 已有音频挑选不能当作最终验收

- 何忆卫参考目录实际有 **488 个音频文件**，存在专业的 UI、攻击、命中、技能、状态和 BGM 分类。
- 已复制的 13 个 `h_*.wav` 仅是候选资产，不等于已经证明适合本项目。
- 文件时长可由 `ffprobe` 可靠核对，但此前频段质心推算只扫描少量频点，且采样处理存在问题。
  **此前给出的精确 Hz 值不作为选音依据，也不写入验收结论。**
- 没有完成实际听辨，不能使用“已经试听”“声音一定更清脆”等措辞。
- 素材文件名、短时长和频谱数据只负责筛选候选；最终要通过等响度 A/B、混战试听与设备实听。

## 4. 总体美术方向：废弃反应设施 + 活性物质实体

### 4.1 一句话目标

> 玩家操控一个有重量、会变形的活性原子核心，穿过具有金属、玻璃和腐蚀痕迹的反应设施，
> 与具有明确剪影和动作意图的反应实体战斗；UI 像嵌入世界的仪表和实验记录，而不是霓虹网页组件。

### 4.2 三个美术支柱

1. **实体感**：轮廓、内部暗面、材质高光、接地阴影组成主体；发光只是辅助，不是主体本身。
2. **化学身份**：角色、武器、场景的结构可关联到反应/器械，不靠到处画公式和苯环代替设计。
3. **战斗优先**：危险、玩家位置、敌人意图比表面装饰重要；低质量关闭 Bloom 后仍成立。

### 4.3 “去网页感”不是“弃用 SVG 或 DOM”

| 现象 | 改进方向 |
|---|---|
| 空心圆、正三角、圆角方框之间只换色 | 建立实体剪影、重量差异、结构和功能部件；内层细节在小屏下可删 |
| 所有单位全体 ADD、透明线框、同样的辉光 | 主体普通混合；金属/玻璃/陶瓷分层；ADD 只给热点和短特效 |
| 主体、电子轨道、粒子争抢相同亮度 | 轨道保持机制可读，主体占视觉重心；环境降低饱和度与对比 |
| 面板都是大圆角、发光边、渐变按钮 | 材质底板、结构边、压角、编号、层级化图标；光只用于选中/危险 |
| 无动作，只有整体缩放/漂浮 | 预备、挥动、后坐、收势、受击、死亡；变形围绕功能部件发生 |
| 世界交互物像文字按钮 | 终端、样本箱、商人工作台、撤离设备都有实体轮廓与近距离操作反馈 |

**禁止以“所有单位都不对称”作为统一原则。**稳定护盾/容器可以对称；
自由基的缺口、光子的方向性等只在能表达功能时使用不对称。

### 4.4 配色与材质

以下为初始视觉令牌，投产前通过纵切截图校准，不全局覆盖已有语义色：

| 用途 | 初始方向 | 约束 |
|---|---|---|
| 环境底色 | 深石墨 `#11181B`、湿金属 `#263238` | 不用纯黑把材质全吃掉 |
| 中性材质 | 钢灰 `#5D7076`、陶瓷白 `#C7D2CC` | 先用明度区分面，再用色相 |
| 玩家轮廓 | 灰白实体 + 少量青白活性热点 | 染料改变活性部位，不把整人染成敌人配色 |
| 氧化/还原 | 延续现有两态强调色 | 外壳基色与反应热点分离，不能改变模式识别习惯 |
| 敌方危险 | 延续红/橙预警语义 | 治疗/绿色敌人不能仅凭绿色被读成安全对象 |
| 可交互 | 克制的金属暖光或青色指示 | 与危险标记靠形状、运动和文字共同区分 |
| 稀有度 | 现有普通/稀有/传说色作为小面积标签 | 不用整张彩色发光底板表达稀有度 |

环境表面细节以“粗/中/细”三层制作：先轮廓与接缝，后腐蚀污迹，最后微纹理。
禁止用密集噪点、霓虹描边或 Bloom 堆出所谓质感。

## 5. 音效系统完整方案

### 5.1 单一播放入口与资产契约

拟在开发阶段新增 `src/game/audio/`，逐步迁移，不立即删除旧入口：

```text
audio/
  AudioDirector.ts       游戏级服务，生命周期、设置、场景状态
  AudioCatalog.ts        语义事件 → soundId/变体/混音参数
  VoiceAllocator.ts      真实活跃声部、优先级与分组去重
  MusicDirector.ts       状态选曲、intro/loop、淡变和 ducking
  PhaserAudioBackend.ts  Phaser/WebAudio 实际播放与结束通知
```

建议事件契约（字段为计划，不是已实现 API）：

```ts
interface AudioRequest {
  event: AudioEventId;      // 语义事件，如 weapon.melee.swing、combat.hit.light
  eventId?: string;         // 对同一个判定去重，避免命中/电子弹出/浮字各播一次
  sourceId?: string;
  position?: { x: number; y: number };
  intensity?: number;
  reactionMode?: 'oxidized' | 'reduced';
  localPlayer?: boolean;
}
```

解析顺序：

```text
判定事件 → 合法语义 ID → 候选变体 → 已注册的 soundId
        → 设置/距离/强度 → 优先级与去重 → 实际播放 → 结束释放声部
```

- loader 与播放端必须使用同一个 soundId 生成规则；不能一端注册文件名、另一端播放语义名。
- `GameScene.playSfx()` 和 `Menu.uiSfx()` 先作兼容转发，再逐批清理旧 key。
- 发布测试中未知事件/资产未注册视为失败；生产环境可静默跳过，但诊断记录只报一次。
- 音效的变体选择使用独立表现随机源，**不得消耗战斗 RNG**，静音不能改变掉落和暴击结果。
- `playTone()` 不继续裸建无限制 oscillator；保留的合成反馈也进入混音和生命周期管理。

### 5.2 声音身份与事件覆盖

| 事件组 | 听感目标 | 同步位置 | 初始变体数 |
|---|---|---|---:|
| 光剑启动/挥动 | 轻薄电极激活 + 有方向的切风 | 招式启动/活跃段，不能每帧播放 | 3 |
| 光剑命中 | 硬质短瞬态 + 少量裂解颗粒 | 实际有效命中 | 3 |
| 反应炮发射 | 短促蓄压释放，区别于光剑挥动 | 弹道创建 | 3 |
| 反应炮命中 | 玻璃/陶瓷撞击 + 反应爆散 | 弹道到达真实命中点 | 3 |
| 氧化/还原 | 同一武器主体，附加裂解/注入的小差异 | 实际反应，不改成两个不相关的武器音色 | 每态 2 |
| 暴击/破层 | 普通命中基础上增加清晰高亮层 | 对应判定，不能给所有命中同样强度 | 各 2 |
| 普通击杀/精英击杀 | 短碎裂/更厚收束音 | 真实死亡 | 各 2 |
| 受伤/护盾吸收 | 受伤近身冲击；护盾薄膜脆响 | 扣血/吸收实际发生 | 各 2 |
| 前摇/冲撞/射线/熔毁 | 可识别的启动音；危险高于装饰 | 与可读预警同时开始 | 每类 1–2 |
| 掉落/券/装备/祝福 | 大小层次不同的兑现反馈 | 获得一次播一次，密集拾取可合并 | 每类 1–2 |
| UI/选择/购买/拒绝/离开 | 简短、安静、有一致机械触感 | 触摸、鼠标、键盘共用同一语义 | 每类 1–2 |
| 撤离/死亡/通关 | 独立的结算动机，不借用普通敌人死亡音 | 结算成功/失败 | 各 1 |

时长目标是听感设计区间，不是硬性截断：普通攻击主体优先 0.1–0.35s；
重击和重要反馈可到 0.3–0.7s；状态/结算可有更长尾音，但高频音不能长尾连续覆盖。

### 5.4 选音与加工流程

1. **溯源**：记录原路径、hash、来源项目、原始用途、授权状态。
2. **初筛**：文件可解码、时长、响度、峰值、前导静音、尾部静音、音色标签。
3. **听辨**：耳机、手机外放至少各一轮；区分启动、接触、碎裂、警报，不靠文件名猜。
4. **等响度 A/B**：旧音与 2–3 个候选按相同听感音量比较，不能“更响就是更好”。
5. **场景试听**：单击、连续攻击、群怪、Boss、BGM 同时播放；检查疲劳和掩蔽。
6. **定稿加工**：裁掉无用静音、短淡出防爆音、必要的 EQ 和限峰；保留原件。
7. **输出**：短音优先浏览器实测支持的压缩格式；不默认所有文件一律 22.05kHz 单声道 WAV。
   电弧/刀刃的高频和立体空间线索需要保留；有明确收益才降采样。
8. **生成清单**：脚本产出 asset key、大小、解码时长和 provenance，进入加载对账测试。

**授权门槛**：何忆卫是参考工程，其 assets 包含其它商业游戏音画素材的迹象。
用户允许参考项目取材不自动解决底层版权。开发预览可标注“临时参考素材”；对外发布前
逐项确认许可、替换成可分发素材或自制。缺授权项不能标记为“可发布”。

### 5.5 混音与并发：初始调音参数

以下是开发起始值，不冒充已实测的最终参数：

| 项 | 初始值/规则 | 验收方向 |
|---|---|---|
| 总线 | master → music / ambience / combat / UI | 主音量与分类静音实时生效 |
| 活跃短音预算 | 移动端起始 8，桌面起始 12 | 追踪真实完成/stop，不能用每秒次数冒充并发 |
| 同资产重叠 | 初始上限 2 | 同波形不在群战堆成噪声 |
| 危险保留 | 普通音不能占满全部危险额度 | 受伤/熔毁不被拾取或 UI 挤掉 |
| 抢占 | 重要危险可淡出最低优先级装饰音，淡出约 20–40ms | 避免硬切爆音与丢失关键反馈 |
| 事件冷却 | 按挥砍、命中、拾取、UI 单独配置 | 取消所有音共用一个全局 45ms 否决门 |
| 群体命中 | 同攻击 eventId/时间片内合并低价值重复反馈 | 10 个敌人不代表必须叠 10 个同音 |
| 音高变化 | 同一功能的 3–5 个变体；小幅 rate 抖动起始 ±3–6% | 不把枪声随机混入刀剑音族；警报音不随机变形 |
| 空间声 | 轻量声像/距离衰减；本地受伤不被距离衰减 | 玩家能辨别近身和远处，不能左右声道极端断裂 |
| music ducking | 关键反馈期间音乐降低约 3–6dB，释放约 0.2–0.5s | 不持续泵动，也不靠全面加响实现穿透 |

优先级以信息价值排序：**玩家危险/受伤 > 关键命中与破层 > 本地武器动作 > 普通敌人动作 > 收益 > 装饰 UI**。
当前 `impact` 高于 `alert` 的全类排序需要细分，不把每次普通命中都放到致命警报之上。

### 5.6 手势与生命周期

- 在真实 `pointerdown/click/touchend/keydown` 回调内解锁或恢复；不能假设 update 中的播放仍有浏览器手势授权。
- 优先复用 Phaser 自带音频 context 与 unlock 机制，不另造平行 AudioContext。
- 解锁前：保留最后一次音乐意图；过期的战斗/UI 短音丢弃，避免解锁后突然补放一堆。
- 失焦/后台时暂停非必要播放；回到前台检查 `suspended/interrupted`，必要时等待下一次有效手势。
- 场景 restart、死亡、返回大厅释放属于该场景的声部与监听；音乐服务仍为游戏级单例。
- 不用 `audioUnlocked=true` 永久假定此后永不再次 suspended。

### 5.7 BGM 设计

单场景引擎结构不等于只有一种音乐情绪。根据玩家体验定义：

```text
标题/大厅 → 探索 → 战斗 → 精英/Boss → 撤离倒计时 → 成功/失败 → 大厅
```

- 先选 3 个主曲族：大厅、探索/普通战斗、Boss；撤离初期可用节奏/低频层强化，不必新增整首。
- 普通战斗清空后保留短暂余韵，避免反复进出战斗造成曲目抽搐。
- 优先尝试参考项目 intro→loop 与 0.8–1s 淡变；实际 loop 接缝需试听，不保证不同素材天然无缝。
- Boss 二阶段优先做强度变化；没有合法分轨时不声称已实现多 stem 自适应音乐。
- 将现有 5 首 adven 保留作 A/B 基线，不预先断言“不适合”或“必须全保留”。
- 采用加载分组：启动只加载菜单和核心短音，音乐按需求准备，避免首次等待全部约 22MB BGM。

## 6. 角色、武器与动作资源方案

### 6.1 玩家主体

- 保留氢原子核心身份，但建立“外壳/晶核/活性区域”三层，避免仅一组同心圆。
- 身体暗面在普通混合下可见，轮廓高光控制面积；电子轨道独立于美术外壳绘制。
- 中立待机不强行指向某方向。近战 360°攻击不能因画面上的朝向让人误判只有正面能打。
- 反应炮的朝向提示跟真实瞄准向量走；主体变形不能改变碰撞中心。

### 6.2 普通敌人：以实际代码角色为准

| 资产/行为 | 剪影与材质方向 | 动作重心 | 必须读出的信息 |
|---|---|---|---|
| 自由基 / chaser | 有未配对缺口的活性晶团、短尖刺 | 前压→收束→接触爆裂 | 快速追击和近身攻击意图 |
| 氧化剂 / ranged | 耐压容器、氧化热点、明确喷口 | 蓄压→喷射→回缩 | 发射方向和下一发准备 |
| 聚合物 / tank | 交联聚合装甲、低矮厚重基座 | 压低→冲撞→制动 | 不能只画一个缠绕环，必须有重量和冲撞方向 |
| 酸液滴 / acid | 黏液体、腐蚀核心、湿反光 | 摇晃→积聚→溅落 | 本体与危险酸池是两个层次 |
| 还原剂 / healer | 反应囊与回流管线、补充作用部件 | 储能→注入→回流 | 友方敌人的恢复来源 |
| 光子 / sniper | 聚焦镜组与细长发射轴 | 对焦→射线→散热 | 射线起点/方向，提示不盖住实际路径 |
| 单体 / summoner | 有多个接合口的培育母体 | 端口打开→生成→合拢 | 新敌人来自哪里，召唤前摇明确 |
| 催化剂 / shielder | 多孔载体与屏障发生结构 | 活性位开启→屏障输出 | 它是护盾支援，不标成治疗单位 |

每类常规配色沿用，辅以剪影/材质/动作区别；关闭颜色或染色改变后仍不完全依赖色相认敌。

### 6.3 四个现有 Boss

| Boss | 主体方向 | 阶段表现，不改判定 |
|---|---|---|
| 滴定巨像 | 巨型反应容器、液位、滴定部件 | 酸碱状态影响液体与热点；原有预警照常显示 |
| 电解领主 | 双极电极、绝缘基座、导电桥 | 电弧连接点/极性明确；不靠全屏蓝光表达强度 |
| 链式反应母体 | 多腔反应体、可辨识的链节与孵化口 | 连锁/分裂时真正打开相应结构，不整图缩放代替 |
| 氧化之主 | 高温反应炉、散热裂隙、氧化热点 | 升温表现分层；熔毁倒计时和危险轮廓最高优先 |

不创建“第 5 个 Boss”来匹配旧注释；当前数据实际为 4 个。

### 6.4 最低动作集与生产策略

先以“单体素材 + 部件/骨骼式变形 + 少量关键帧”完成纵切，确认风格后决定是否批量序列帧。

| 对象 | 第一阶段最低动作 |
|---|---|
| 玩家 | 待机、移动响应、近战起手/挥动/收势、远程后坐、冲刺、受击、破电子/死亡 |
| 普通敌人 | 待机、移动、各自攻击前摇/活跃/回收、受击、死亡 |
| 支援/召唤 | 额外的端口/屏障/注入动作，而非同一套缩放脉冲 |
| Boss | 待机、各核心招式三段、阶段转换、受击、死亡 |
| 世界交互物 | 关闭/可用/使用中/已耗尽 |

所有时长由现有判定窗口驱动；不为了动画好看改前摇秒数。
动画参考帧以 60fps 标注，运行时按 delta 驱动，在 30fps 下仍与判定同步。

### 6.5 资产清单下限

- 1 个玩家主体、8 个普通敌人主体、4 个 Boss 主体、2 个武器表现族。
- 8 套普通敌人的角色动作配置、4 套 Boss 阶段/动作配置。
- 精英版本首期使用结构附加件/明显标记，不为每类重复画完整主体。
- 出图源稿保留矢量或分层文件，运行资产可统一烘焙成图集；不要求一次全部改成 PNG。
- 单位以固定锚点与脚底/接地点对齐；阴影单独管理；贴图画布与世界尺寸独立。
- SVG viewBox 与 raster 尺寸可以按分辨率策略不同；正确约束是**宽高比、锚点、轮廓与显示尺寸**，不是所有数值必须相等。
- 相同宽高比的 192→256 等比 raster 放大并非“非等比拉伸”，不再按此前错误诊断修改其它资产。

## 7. 场景、格栅地面与通行信息

### 7.1 用户上传参考图的应用

参考图是黑/深灰底、细密的横向栅条、有弱明暗起伏；作为**材质纹样方向**使用：

- 形成工业格栅的金属横条与暗孔，不使用原先“绘制几条横竖线”的图标式网格。
- 它不是 UI 背景的通用铺图，也不是阴影或不可通行区的唯一识别码。
- 上传图较小，不直接大面积拉伸；开发时重绘可平铺素材、验证接缝与低分辨率闪烁。
- 本轮只记录参考方向，不生成或导入新纹理。

### 7.2 可通行与不可通行：一份事实源

| 类型 | 视觉 | 数据 |
|---|---|---|
| 可通行地面 | 平面、半透明格栅、克制接缝，底层可见 | 不具有真实阻挡碰撞 |
| 可走浅台 | 贴地格栅/薄边，不出现暗示墙体的厚侧壁 | `collidable=false` |
| 不可通行障碍 | 实体顶部、可见侧壁、接地暗边、必要的边缘警示 | `collidable=true` |
| 装饰/器皿 | 小面积、靠边、视觉上不冒充高墙 | 默认不新增碰撞；若需碰撞必须同时改数据和显示 |
| 危险但能进入区域 | 使用危险边界和运动提示，而非墙体 | 伤害区域，不等同于阻挡 |

当前块有“高度较高但因走廊/间距规则不设碰撞”的可能，因此**仅按 height 绘侧壁仍会骗人**。
显示规则必须以最终 `collidable` 为准，不可只加亮边就宣称“所见即所撞”。

半透明指材质和视觉占位，不是把所有背景减到看不清。初稿目标：格栅暗底约 0.12–0.22 alpha，
栅条/接缝约 0.25–0.45 alpha；在实际镜头、手机亮度下调，不作为最终参数。

格栅不能在障碍顶面随机继续铺一层可走纹样；地面材质应避开阻挡占地或正确在其下方。

### 7.3 环境资产首批套件

| 套件 | 首批需求 | 用途 |
|---|---|---|
| 地面 | 2 个格栅尺度版本、1 个陶瓷/金属过渡、少量腐蚀/积液贴花 | 相同设施语言，避免地面全部同花纹 |
| 障碍 | 3 个体量的反应容器/绝缘块，顶面与侧面可组合 | 真实阻挡、绕行与掩体外观 |
| 地物 | 烧杯、烧瓶、滴定架、管线、结晶簇、样本架 | 设施身份；不新增花草 |
| 交互 | 样本箱、诡商工作台、实验日志终端、染色台、冷却池 | 实体与状态变化可见 |
| 出口/撤离 | 门框、下一房类型徽记、稳定化设备 | 选路与撤离风险信息 |
| 大厅 | 实验主台、遗物柜、武器架、染色台、仓库模块 | 与局内同世界，不像几个悬浮网页按钮 |

环境分为前景、玩法平面、远景三层；前景不得挡住交互和危险区。
不要为装饰添加大批动态对象；静态表面优先图集、批绘或烘焙，保留现有裁剪与生命周期清理。

## 8. VFX、声音与动作同步

### 8.1 统一三段式

| 段 | 视觉 | 声音 | 原则 |
|---|---|---|---|
| 前摇 | 功能部件动作、凝聚/蓄压、真实危险范围 | 低强度可识别启动音 | 完整覆盖现有反应窗，不以纯亮度取代形状 |
| 命中 | 短刀光/击中点/粒子反弹 | 真实接触音；关键命中加一层 | 空挥只播挥动，不能补命中音骗反馈 |
| 余韵 | 少量散逸/碎片/短附着 | 较弱尾音 | 延续材质，但不拖尾遮住下一次攻击 |

### 8.2 强度层级

- 普通攻击以主体动作 + 少量命中粒子为主，不每下大面积白闪或震动。
- 暴击/破层/精英击杀用额外视觉与声音层，仍遵守统一事件去重。
- Boss 转阶段、熔毁、撤离结果才使用屏幕级强调。
- 既有 `registerHit` 的白圆、电子轨道与机制数字先保留；纵切中评估遮挡再决定改法。
- 粒子继续共享池、小尺寸、随机溅射与设备预算；不新增“每个单位一台独立发射器”。
- VFX 的装饰随机与伤害 RNG 分离；静音、低画质、隐藏背景装饰不能改变结果。

## 9. UI 重设计与移动端约束

### 9.1 一套仪表/实验记录语言，三个层级

1. **战斗 HUD**：小面积仪表；电子、温度、武器、券只保留当前操作需要的信息。
2. **短选择面板**：祝福/事件/商店；收益与代价优先，设备质感来自边框/图标，不靠炫光。
3. **长管理面板**：遗物/武器/装备/染色/设置；层次、滚动与固定返回区明确。

保留 DOM 面板的可访问性与布局能力，不把全部界面强制迁进 canvas。
表现材质、字体、图标和交互一致，比实现技术本身更能消除网页感。

### 9.2 具体改造

- 主面板使用石墨/金属仪表底板、小切角/压角、少量横纹和编号；减少统一大圆角胶囊卡片。
- 稀有度、状态、模式使用专门小标记，不靠整面阴影光晕。
- 字体分工：中文内容清晰的 UI 字体，数值使用 tabular numerals；不把所有长中文都交给 monospace。
- 表情符号逐步改成统一小图标集，避开不同系统字体导致的视觉差异。
- 选中、购买成功、拒绝、离开共享动作节奏；悬停仅作桌面附加态，触摸不是悬停的缩水版。
- 信息内滚动，关闭/返回区固定或 sticky；内容再长也不把出口推到屏外。
- 事件结果面板提供明确“继续/离开”，不显示未实现的 E 键出口；退出未结算事件的规则单独确认并一致执行。

### 9.3 20:9 与真实手机 CSS 像素

测试至少覆盖：800×360、844×380、1000×450 CSS 像素，桌面 1280×720；
并补 844×390 等常见非精确 20:9 手机比例和带安全区横屏。

**内部分辨率 1920×864 只是镜头比例，不等于已完成移动端验证。**
真正要同时设置 CSS viewport、touch、DPR，并走正常加载路径。

初稿布局约束：

- 交互按钮目标热区至少 44 CSS px；小图标可以更小，但热区不能只剩 20px。
- 短提示/数值正文起始 12–14 CSS px，长说明优先 13–15 CSS px；标题起始 18–24 CSS px。
- 顶部 Boss 信息不铺成半屏巨条；左下生命信息整块预算约 22–28% 屏宽。
- 短选择面板宽度 `min(设计宽, 视口可用宽)`，高度封顶可用高度；标题/按钮不被裁。
- 安全区、手势条、触摸控件区域必须与 HUD 共用布局口径；关键显示不处于摇杆和攻击手指覆盖区。
- 中文字符宽不能按所有字均为 `0.6em` 估算；按真实文字 bounds 做换行/缩放。
- 字号与几何虽已分离，文本高度和字符串长度仍需进入布局，不用“零溢出列表为空”替代观感评审。
- 操作出口回归测试覆盖事件、祝福、状态、战报、设置、大厅各管理面板。

## 10. 工程与资产集成边界

### 10.1 拟涉及文件（开发获批后）

| 区域 | 文件/目录 | 改造方式 |
|---|---|---|
| 音效清单 | `src/game/data/sfx.ts`、拟新增 `src/game/audio/` | 补齐解析与播放、别名迁移、混音及生命周期 |
| 音效加载 | `AssetLoader.ts`、`BootScene.ts` | 清单对账、分组加载、错误诊断，不提前放行玩法必需资源 |
| BGM | `BgmManager.ts` | 渐进转发到 MusicDirector，保留旧曲 A/B 基线 |
| 场景调用 | `GameScene.ts`、`LobbyScene.ts`、`Menu.ts` | 改为语义事件，减少重复声源与裸 oscillator |
| 主体/动画 | `assets/sprites/`、拟新增视觉配置/角色表现模块 | 不更改战斗 Runtime 判定结构，只替换表现边界 |
| 地面/障碍 | `biomes.ts`、地形表现代码、`assets/sprites/decor/` | 统一通行视觉，格栅纹样与阻挡数据一致 |
| UI | `index.html`、`Menu.ts`、`UIScene.ts`、`uiScale.ts` | 设计令牌、资产图标、结构布局及真实手机尺寸 |
| 测试 | `tests/`、拟新增 `playtest/` | 纯逻辑测试与真实运行场景、截图/听音报告 |
| 文档 | 本文、拟新增资产来源表/试听记录 | 记录原始、候选、选用、替换、授权状态 |

不要把 8000 行 GameScene 作为整体重写目标。按服务入口和表现模块逐段抽离，
每个阶段都保留可运行版本，便于发现是哪一批引入了变化。

### 10.2 资产规范

- 每项资产记录 ID、用途、源路径/hash、作者/来源、许可、工作源稿、输出文件、尺寸、锚点、变体。
- 音效带类别、触发时机、测量时长、响度/峰值、同音族和试听结论；不只记录文件名。
- 主体带玩法中心、接地线、各动作的读意点；裁切不能改变角色世界位置。
- 图集采用透明边 padding/gutter；纹理尺寸先以 1024/2048 级可控预算规划，按实际 Phaser 上传与手机测试确定。
- 格栅高频细节在手机/缩放时出现摩尔纹就换粗一级 LOD，不靠关抗锯齿掩盖。
- 微纹理不能成为大面积“重复的同一污渍”；统一光照方向，不能把纹理阴影烘焙成矛盾方向。

### 10.3 性能约束

- 复用现有 low/medium/high，粒子预算沿用 360/800/1400 与负载系数，不新增质量档。
- 低质量关闭 Bloom 后：主体边缘、关键预警、通行提示仍应清晰。
- 新材质优先静态图集/烘焙；不为每片格栅新建 mask/filter。
- 背景、地物和声音的生命周期可追踪，restart 之后对象/声部/监听数量不线性上涨。
- 性能在固定场景前后比较；软件渲染 headless 结果不能冒充真实手机 FPS。
- 目标设备的基准帧时间退化超过约 10% 时先减表现，不直接降目标帧率掩盖新增负担。
- 首次必需资源的字节数/耗时不增加而不解释；新 BGM 分组加载必须有可取消和无声容错。

## 11. 验证方法：禁止把模拟探针当成实机完成

### 11.1 可信测试入口

- 开发阶段提供 DEV-only 的显式测试契约，暴露真实游戏所用的状态、场景状态、音频诊断。
- 不依赖带不同 URL/query 的动态 import 改“另一个模块实例”的状态。
- 不在循环中反复 start 同一场景；等待其完成，重启行为必须由专门用例驱动。
- 不强停 BootScene 然后声称证明资源/纹理正确；快速启动只能跳过演出，仍完成必需资源加载。
- 不用 iframe 验证 WebGL。
- skill 的 harness 在 Chromium 未安装成功时判为“验证工具不可用”，不能把管道 `tail` 返回 0 当成测试成功。

### 11.2 验收场景

| 场景 | 内容 | 必须记录 |
|---|---|---|
| A 正常启动/大厅 | 冷启动、点击进入、打开关闭管理面板 | 加载 key、404/解码错误、手势解锁、界面截图 |
| B 单武器循环 | 两武器各连续攻击、空挥、实际命中、氧化/还原切换 | 声音触发日志 + 有声录屏，不能只看 manifest |
| C 群怪 | 3–8 个现有敌人，连锁/掉落/拾取同时发生 | 声部峰值、抢占/合并结果、疲劳与遮挡 |
| D 危险 | 近战前摇、冲撞、射线、低血、熔毁 | 玩家能看到/听到何时危险，背景不掩蔽 |
| E Boss | 每个核心招式、各阶段与死亡 | 预警与动作/声音同步，Boss 音乐淡变 |
| F 收益/交互 | 祝福、事件、商店、样本箱、撤离/死亡 | 收益/代价可读，触摸离开/继续路径 |
| G 移动端 | 实际 20:9 CSS 视口 + touch + 安全区 | 真截图、实际 bounds、手指覆盖区与控件热区 |
| H 生命周期 | 场景重启 10 次、后台/前台、音量/静音切换 | 对象、cullables、监听、声部无累计泄漏 |

### 11.3 音效必须通过的自动验收

1. 每个事件在目录里可解析成实际注册的 audio key；当前历史别名也有明确处理。
2. `Menu.uiSfx` 和战斗音全部走同一入口，设置/静音一致生效。
3. 有变体且跨多次播放不连续复读同一波形；短音率抖动不超配置。
4. 自然结束、手动 stop、场景关闭、抢占四条路径都释放声部。
5. 普通音已占满预算时，关键危险仍可启动；同攻击事件不会重复收到几次命中音。
6. 音乐在静音/切场景/后台时不会叠加；准备未结束的曲目不能迟到覆盖新场景。
7. 静音与否不改变战斗随机序列。

自动检查不能证明“悦耳”和“有力量”。音效听辨、手机外放、连续战斗疲劳测试另列人工门槛。

### 11.4 视觉必须通过的人工验收

- 关闭 Bloom、缩到手机镜头后，玩家与至少三类敌人仍可凭剪影区分。
- 一张固定镜头截图能读出玩家、危险、通行、交互四类信息。
- 格栅有上传参考的材质感，但不闪烁、不遮盖危险、不会给阻挡块贴上可走纹样。
- 动画有准备、执行、回收，不靠一段整体放大代替全部动作。
- HUD 和所有面板的触摸出口始终可见；不是只断言没有越界。
- 同一纵切场景的新旧有声录屏/截图并列评审；不以“SVG 更长”“像素亮度更高”判定美术更好。

## 13. 风险、选择与开发授权

| 风险 | 处理 |
|---|---|
| 参考资产有授权风险 | 原型/正式分别标记；对外发布前必须闭环，不以仓库公开等于可商用 |
| 原型只有漂亮大图，缩小全糊 | 先手机实际镜头纵切，再批量生产 |
| 音画表现改了玩法结果 | 装饰 RNG 独立，判定与身体中心不改，固定场景回归 |
| 清单正常但仍没声音 | 注册 key↔实际播放双向对账；禁止空 catch 掩盖验收失败 |
| 更多材质/尾音让混战变糊 | 关键层优先、普通层限密度，静态烘焙和真实声部释放 |
| 新视觉再次被觉得“网页感” | P1 方向确认是停止门槛，不先改完全部素材再给用户看 |
| 移动端“数值正确”但体验差 | 必须真 CSS 视口、touch、截图、有声录屏及触摸流程 |
| 环境无法截图/播放音频 | 记录为未验收，不强跳 Boot、不用像素采样冒充观感 |

### 13.1 本草案替用户做出的暂定选择

1. 推荐“废弃反应设施 + 活性物质实体”，而非换成人形角色或纯赛博网页面板。
2. 保留化学主体、机制轨道和既有配色语义；先改变材质/动作/层级，不改玩法。
3. 何忆卫优先作为方法与候选资产来源；不默认其所有素材可用于正式发布。
4. 先做可评审纵切，再批量音画生产；不把当前未提交 SVG 自动定稿。
5. 音乐可以按 roguelite 的体验状态切换，取消此前“单场景不需要 intro/loop”的武断限制。

这些选择都可在审阅时修改。**本文件写成不代表开发已启动。**

### 13.2 启动条件

- 用户后续明确授权“开始开发”，才开始 P0 的实现与资源生产。
- 若授权同时确认本文方向，按本文执行；若指定调整，先更新对应段再实施。
- 仅继续阅读/审阅计划、发送参考图或补充需求，不视为自动开发授权。
