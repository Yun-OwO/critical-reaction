# 临界反应：全局升级逐项执行规格

> 修订：2026-10-14，R2；接续 `docs/全局风格与性能UI玩法升级计划.md`。
> **本文件是计划，不是开发授权。当前不改游戏代码，不生成资源，不切GPU，不构建APK，不发布，不关机。**
> 后续开发模型的执行入口为本文件。它定义要求、默认实现、实验顺序、阻塞处理与完成证据；设计理由和研究链接见主计划。
> 本文件中所有拟建文件/API、参数与测试都尚未实现，不能从文档存在推断游戏已有能力。

## A. 阅读与执行规则

### A1. 冲突优先级

最新用户指令 → 本文件 → `全局风格与性能UI玩法升级计划.md` → 旧音画计划/roadmap。

- 旧“实体外壳优先”“地面横向条带”“低档关闭Bloom”“像素采样即可美术验收”不再作为指导。
- 用户要求的多层屏幕空间反射为必做项；地面镜像/平面倒影只能作为对照，不得默认顶替SSR。
- 用户推荐TAA/FIFO，不等于要求伪造网页不具备的API；TAA必须评估，FIFO明确说明平台边界。
- 要求的PBR写实是光影/材质风格，不是新增厚外壳、写实贴照片或把矢量主形改成复杂3D模型；细节质量/采样步数以能满足联合验收的最低成本路径实现。
- 主角与Boss大范围华丽特效是本轮新增明确要求，不是可随意删除的装饰。
- 不再研究是否要换引擎：保留现有Phaser 4和Web/Capacitor架构。

### A2. “明确”不等于捏造实测结果

本文件只使用以下四种标记：

| 标记 | 开发时的含义 | 是否允许开发模型自行修改 |
|---|---|---|
| **MUST** | 用户要求或防止事故的约束 | 不允许删改；未通过记为阻塞/失败 |
| **INIT** | 开发起始参数，第一次实现必须使用此值 | 可以根据对照证据调参，但必须记录旧值、新值、理由和结果 |
| **EXP** | 必须按指定步骤完成的可行性实验 | 可以判实验失败，不得冒充完成或自行替换MUST |
| **LATER** | 本轮不默认实施的扩展 | 不执行，除非用户另行授权 |

不知道性能或无法测量时写“未测/阻塞”，不能补填预计结果。审美形容词后必须有实现/检查项；“优化完成”“丝滑”“PBR”“全程60帧”必须有对应证据才能记为通过。

参数变更流程固定：保留原值基线 → 同设备/视口/seed至少3次对照 → 写old/new与帧时间、观感影响 → 验证R要求未削弱 → 再更新参数。未能测到GPU/无法人工审阅的项只能implemented-unverified；不能以改参数逃过MUST。来自源代码的已有时序/伤害范围不是INIT装饰参数，必须按H2审阅变更。

### A3. 完成状态

任务状态仅允许 `planned / doing / implemented-unverified / verified / blocked`。

`verified`必须同时有：提交SHA、实际修改文件、测试命令与退出码、正常启动运行证据、对应的人工观感/实机结果。没有GPU时间工具不等于没有GPU成本，无法确认就说明证据缺项。

**不要一口气执行全部任务。** 每次只执行一个任务ID或明示的一组依赖任务；完成检查后提交，再继续。先完成可测纵切，不批量替换所有精灵后才查帧率。

## C. 美术与材质的制作规格

### C1. 造型、颜色与线宽

**MUST**：主形只使用正圆和封闭直边多边形；次形最多两个视觉组，现有电子轨道作为机制层单独管理。文字、射线路径、轨迹和投影椭圆是功能例外，不为例外扩大有机造型范围。

**INIT（以最终CSS像素为单位，不是纹理像素或世界单位）**：

| 项 | 起始值 |
|---|---|
| 主体轮廓亮芯 | 1.5 px；转角连接用miter并限制尖角外扩 |
| 次形轮廓 | 1.0 px，亮度低于主形 |
| 主体窄辉光 | 亮芯外6 px，柔和衰减，无不透明外壳 |
| 环境结构线 | 0.8 px；不能亮于玩家主形 |
| 世界危险边界 | 2 px，正文/危区不经过重模糊 |
| 明暗面 | 非发光填充最多3档；暗面线性亮度为受光面的0.35倍起始 |
| 直线排线 | 间距6 px、线宽0.7 px、alpha=0.12；物体最终尺寸<32 px时移除排线，不移除明暗面 |

圆形不能通过非等比scale变椭圆来演示“夸张”；通过内部层位移、亮度、旋转或粒子变化表达。地面正圆按统一投影可呈椭圆，不改变其世界形状。

固定初始令牌：背景 `#070B14`、暗材质 `#101726`、正文 `#DBE7F3`、次级正文 `#A5B7CA`、中性亮芯 `#EAFBFF`、交互青 `#45E8FF`、特殊紫 `#B07CFF`、危险橙红 `#FF6A4D`。氧化/还原与各Boss主题色从现有真实配置取，不把敌人和玩家主题都强制改青。

造型判例：正圆主核＋一个菱形内层、封闭三角主形＋一个嵌套三角、矩形终端＋切角面板通过；随机贝塞尔外轮廓、厚圆角胶囊、三个同亮并列主体、黑装甲壳包霓虹、点阵噪声替代暗面不通过。圆的正圆限制用于原始主体，不禁止刚体在2.5D投影中的合理变化。

**MUST**：敌方弹道/危险边在主题色之外带统一危险标记；玩家弹道使用不同几何芯/尾迹。电解领主与玩家可能都为青色，因此不能只靠色相区分。

### C2. 资产清单与结构

T03/T04纵切资产固定为：

1. `assets/sprites/actors/hydrogen-core.svg`：主角。
2. `assets/sprites/enemies/free-radical.svg`：近战追击测试对象。
3. `assets/sprites/enemies/photom.svg`：方向/射线可读性测试对象；实际行为绑定必须再次对照配置。
4. 一个现有电解领主Boss精灵：从AssetLoader实际sprite key定位文件，不按名字猜路径。
5. `grid-tile`的96×48菱形周期纹理、一个collidable障碍、一个非collidable高装饰、一个终端。
6. 一个HUD组件、一个二级面板、一个选择卡，用同一令牌渲染。

拟生成图集放 `assets/atlases/`，原SVG保留，不删除其它用户资产；素材来源与派生文件写 `docs/visual-assets-manifest.json`（未来任务创建）。

每个资源条目必须包含：`id/sourcePath/outputPath/sourceHash/license/role/anchor/heightModel/materialFamily/emissiveMask/normalMask/roughnessMask/atlasFrame`。没有法线/粗糙度贴图时字段显式为null并注明原因，不填不存在的路径。

**INIT**：主体离线栅格化2倍目标尺寸；1024/2048图集、frame间4 texel gutter；微粒texture 32×32、完全透明外圈2 texel；画面边界辉光缓冲预留至少当前滤波核半径的padding。

**MUST**：不同DPR/目标尺寸检查线宽和透明边。测试声明通过但采样矩形不对或被padding裁掉，状态仍是未验收。

### C3. 非发光材质

**INIT**：地面金属 roughness=0.55、metalness=0.7；障碍绝缘体 roughness=0.8、metalness=0；终端反射面 roughness=0.3、metalness=0.6。参数用于统一受限材质模型，不能直接假定Phaser原生filter接受这些字段。

统一照明：屏幕左上受光，初始投影光向量归一化自 `(-0.4,-0.6,0.7)`，具体轴向在T01定义。法线方向、明暗面、AO、SSR必须共享该坐标约定，不单独翻转Y后碰巧“好看”。

**MUST**：地面/障碍/终端法线和粗糙度确实改变受光/高光/反射响应；提交切换参数的A/B图与运行证据。发光主体不强加金属壳，非发光暗面允许使用以上材质。

## D. 微粒与主角/Boss华丽演出

### D1. 光雾微粒运动规格

同一共享粒子群提供清晰微粒与低分辨率密度场两种输出，不新增巨型云贴图。粒子运动使用**秒**为单位：

```text
v ← v + (局部涡流 + 共享扰动 + 浮升 + 源事件方向力) × dt
v ← v × exp(-drag × dt)
p ← p + v × dt
D ← Σ(粒子软核 × 寿命alpha)
alphaCloud = 1 - exp(-0.9 × D)
```

这是流体形态的低成本运动模型，不是流体数值求解。**INIT**：

| 参数 | 数值 |
|---|---|
| 微粒可见直径 | CSS 1.5–3.5 px，从闭区间均匀采样；随世界相机变换核对最终可见值，不按每粒CSS反算增加热路径分配 |
| 寿命 | 普通0.25–0.55 s，华丽余韵0.6–1.1 s |
| 初速 | 普通40–120 world-unit/s，华丽80–220；world-unit沿现有逻辑坐标，不另猜投影 |
| 阻力drag | 普通3/s、光雾2/s；不是逐帧固定乘0.98 |
| 淡入/淡出 | 淡入60 ms，末尾寿命30%平滑淡出 |
| 扰动场 | 32×32共享场；64 world-unit格距；15 Hz生成下一场，按dt连续插值，不15 Hz跳粒子 |
| 扰动加速度/浮升 | 扰动向量长度≤60 world-unit/s²；普通浮升0、光雾视觉高度方向15 world-unit/s² |
| 初速方向扰动 | 源方向±0.45 rad；独立表现RNG，不消耗RunRng |
| 粒子密度核 | 核半径为可见微粒半径3倍；以光滑径向权重衰减到0 |
| 叠亮压缩 | 发光E使用连续软压缩；RGBA8累计前预缩放并测试最大叠加，禁止直接clip密度 |

不默认做全GPU粒子/每粒curl-noise多采样。T08先测共享CPU场；若该路径超预算，登记单独算法优化任务，不直接改成大贴图或固定轨迹。

扰动场首轮实现固定为有seed的低频value-noise标量流函数ψ，以共享格点中心差分计算 `(∂ψ/∂y, -∂ψ/∂x)`，归一限幅到表中加速度；对格内粒子双线性采样、两时间场平滑插值。避免每粒计算多次噪声。离开格覆盖范围使用同一seed连续邻块采样，不在tile边突然翻向；float高度仅为表现字段，不进入碰撞。

### D2. 范围大不等于核心不透明

以下上限只作用于**装饰光雾/反射/Bloom**；不能减少真实攻击范围、关掉弹幕或延迟伤害。

定义 `W,H` 为canvas实际可见CSS宽高，`S=min(W,H)`。屏幕面积测量使用正常色彩合成后的SDR线性亮度Y，装饰层增加量为 `ΔY = max(0, Y(withCosmetic)-Y(withoutCosmetic))`。该差值仅离线诊断，热路径禁止readPixels。

**INIT**：

| 演出档 | 触发 | 大范围软辉光/雾包围直径 | ΔY>0.25的高亮面积上限 | 峰值时长 | 微粒单次/序列发射上限 |
|---|---|---|---|---|---|
| G0 | 普通攻击/普通命中 | ≤0.20S | 2%画面 | 50 ms | 24 |
| G1 | 暴击/破层/特殊段命中 | ≤0.45S | 5% | 80 ms | 64 |
| G2 | 主角特殊攻击完整序列 | ≤0.90S | 8% | 100 ms/峰，连续峰间≥150 ms | 180/完整特殊序列 |
| G3 | Boss重招/转阶段/击败 | ≤1.40S | 12% | 120 ms/峰 | 240/招式或转阶段 |

G2/G3的大范围软层可占较大区域，ΔY=0.03–0.15的柔光不是不透明白屏；核心强光限在事件源/接触/真实弹道附近。该表是第一次制作参数，不是已验证的视觉达标结论。

**MUST**：每把现有武器至少一个特殊攻击序列达到G2效果；每个Boss至少一个重招和一个转阶段/击败达到G3效果。大包围范围仍必须可在视频中辨认微粒密度、明暗团和涡散，不以放大空透明边冒充大范围华丽特效。

G0/G1的装饰几何可以短瞬态；禁止所有攻击套同一环形扩张。机制圆环/轨道与真实圆形危区保留，属于信息层，不受“少装饰环”禁令影响。

### D3. 可读性与操作保护

**MUST，所有G档都适用**：

1. UI最后合成，世界特效永远不能盖住摇杆、攻击、冲刺、切换、返回/关闭。
2. 玩家主形和脚点始终存在；玩家周围18 CSS px保护区内，装饰雾alpha不得高于0.08（INIT）。使用柔性过渡mask，不留下硬洞。
3. 敌方弹道主芯/危险边附近6 CSS px内，装饰新增ΔY不超过0.10（INIT）；临近危险时削装饰密度而非削危险亮度。
4. 保护mask只用于重要信息与装饰合成，不让被实体墙挡住的敌人全部透视发亮。实体遮挡与近景装饰遮挡分开。
5. 同屏同时处于峰值的装饰G2/G3事件上限2（INIT）；超过只压装饰发射率/辉光增量，不推迟、取消战斗事件。低优先级装饰余韵先让位。
6. 单次受伤/熔毁不全屏白闪；局部光、边缘反馈和清楚危险提示表达冲击。屏震/缩放参数沿现有反馈表先保留并单独测，无授权不全体加倍。
7. 不为演出锁输入、延迟冲刺或临时更改瞄准。任何技能本来就有的恢复限制单独记录，不能新增“播特效期间不可动”。
8. 真实伤害、光芯、危险边与声音播放请求来自同一事件，触发调度差异≤一渲染帧；实际音频输出设备延迟单独测量，不把请求时刻冒充声音到耳时刻。跟随运动的光源/阴影每帧更新，不用低频跳动。
9. 取消、死亡、换房后不补播过期攻击/危区；纯余韵可以自然结束，但不得留会误导玩家的攻击芯。
10. 减少闪光/动态效果设置关闭亮度脉冲和夸张镜头，不删除伤害提示或让危险仅剩声音。

保护mask具体CPU/GPU实现由T02选择并记录，必须受draw-call/RT预算约束；禁止为了这10条给每粒加一次场景filter。

## E. 渲染实现起点、实验与阻塞

基础逻辑合成顺序固定：底色/静态材质 → AO/非发光受光 → 地面SSR → 按脚点/真实高度遮挡的主体 → 有效弹体/微粒 → 前后光雾与共享Bloom → 可读危险/玩家保护层 → Phaser触控 → DOM HUD/菜单。具体pass合并由T02确认，不能把顺序等同于每步一个全屏RT；辅助depth/normal在SSR之前由相同场景数据生成。

INIT额外RT总占用≤32MiB、常用图集纹理≤64MiB、可见world draw calls告警线100。计数含ping-pong/附件/mip/保留池，不拿下载文件大小当占用；超告警先报告并优化，不直接删除R要求。主像素数/RT尺寸/实际pass逐项写T02/T10记录，禁止未统计就说共享缓冲一定快。

### E1. 辉光与软层

**默认路线**：一套共享emissive缓冲，近/远两尺度模糊，共享云密度场；主形与关键危险/文本从清晰路径合成。禁止旧相机Bloom与新Composer双开造成双曝光。

**INIT**：近光宽高为主画面1/2、远光1/4；双滤波下采样中心＋四角5 taps、上采样四邻4 taps；近光合成权重0.35、远光0.65，按统一线性能量校准，不能直接假设已有`blendAmount`语义相同。T05记录实际RT/pass/taps。

性能档和均衡档都要能看到宽范围辉光；“低步数”只降低采样计算，不把大范围软光删掉。主画面不常态blur，激光芯与文字保持清晰。

### E2. 多层SSR（MUST＋EXP）

**默认实验路线**：固定正交观察的2.5D辅助可见表面缓冲 → 低分辨率有界屏幕射线求交 → 按粗糙度合成3级反射 → 遮挡/边缘置信度衰减。

1. T01定义 view-space坐标、正交相机方向和变换，写正/逆变换测试。禁止直接拿`depthFromXZ()`值或alpha当真实深度。
2. 先覆盖地面、一个带高度的障碍与终端；对它们定义同源表面高度/法线/粗糙度/可见mask。只给真实可见实体写有效辅助数据。
3. 微粒、HUD、透明灯芯不写虚假实体深度。角色参与反射时必须有明确的sprite高度模型和覆盖范围；“按亮度估高度”禁止。
4. **INIT**：射线缓冲宽高1/2；最多16步＋3次命中细化；最大view-space射线长度512已定义世界单位；不命中、离屏、错误面向时返回低置信度并连续衰减。
5. **INIT**：近/中/远粗糙反射输出为原反射缓冲、再降1/2、再降1/4，合成权重由粗糙度确定；不连续显示三张重影。
6. 测试移动光源、掠射角、屏边、反射面遮挡、非反射面、叠层障碍。冻结相机/光源后反射不能随机跳；动态反射每渲染帧更新。
7. 先用1张共享反射源，再测缓存/裁域；记录RT格式和精度。深度packed或半浮点选择必须有误差/支持性测试，不能盲用扩展。
8. **INIT成本线**：HD4400在主验收像素数下SSR阶段GPU P95≤2.0ms、全部GPU P95≤10ms。2.0ms可凭证据内部调预算；整体验收不可降低。

SSR核心计算不得留给模型猜：`R=reflect(I,N)`，I为相机到当前表面的单位入射方向；在view-space沿R步进，将采样点用T01统一投影变换映射UV，与同UV有效表面深度求交。不从地面向上镜像整张color，也不拿shader内屏幕Y当深度。INIT深度命中厚度2 world-unit、掠射自交偏置1 world-unit；对遮挡错误/薄物体做误差测试再调。所有矩阵、远近约定、采样深度范围必须在T01记录具体值并测正/逆，缺任一项停止T06，不能用`any`/魔法常数掩盖。

3级粗糙反射混合固定起点：粗糙度r≤0.5时近/中权重`1-2r / 2r`、远0；r>0.5时中/远权重`2-2r / 2r-1`、近0。合成总能量乘材质反射响应和置信度，不每层全强度ADD。INIT边缘置信度在距画面边24 CSS px内smoothstep衰减；离屏像素不凭空补全。需要替代反射源只能记录为环境补光，不能当SSR命中。

任务结果：真实SSR多层与总体60帧一起过才`verified`。若辅助深度不成立、漏光不可控或预算无法满足，状态为`blocked`，报告失败边界/耗时与至少一种算法优化实验。**不能自动切平面镜像后宣称R04通过**。

### E3. AO与材质

AO用户未限定SSAO算法：默认房间生成时缓存静态接触/凹角AO，移动主体每帧小范围接触遮蔽。**INIT**：静态AO半径16 world-unit、强度0.25，动态接触最大alpha0.22，NORMAL/MULTIPLY正确压暗非发光受光面。

材质以法线、粗糙度、金属/非金属响应、环境光和SSR构成受限2.5D模型。T07核对Phaser本地ImageLight与render node功能；所需响应原生不支持时在共享材质合成层实现，不给每个sprite独立高成本filter。SSAO/GTAO全屏算法属于LATER，不阻塞正确的AO要求。

自建材质shader使用统一的能量分工：非金属F0从0.04起、金属F0向基础色插值，法线控制入射夹角，粗糙度控制高光分布与E2反射层混合；漫反射项随metalness减少，emissive独立加入并进入Bloom。可以烘焙静态受光项，但动态热点与粗糙度响应必须有效。若采用标准微表面模型，以GGX/Smith/Schlick固定为首轮路线并标明是受限2.5D BRDF；若不用该模型，只可标“PBR风格近似”，不能把模块名当物理计算证据。GPU超预算先缓存静态项/减少受光区，不能把材质要求直接删掉。

### E4. TAA与FIFO

- **EXP，TAA**：先具备有效的前后位置/运动数据，再用当前颜色＋历史＋重投影制作小样。INIT历史权重0.85、8帧抖动周期、邻域clamp，UI/危险清晰路径不经TAA。测试高速亮线、微粒、遮挡切换、旋转/换房历史清除。
- TAA抖动首轮固定Halton(2,3)的索引1–8，每轴减0.5，偏移以主画面像素为单位，再转UV；当前/历史深度一致性检查、3×3邻域颜色clamp、失配像素历史权重0。运动矢量覆盖不足的透明粒子不强行重用历史；换房/resize/画质结构切换清空历史，不产生旧房残影。
- TAA保留条件：轨迹鬼影不可在正常速度视频辨认，细线没有持续糊化，CPU/GPU/low帧仍过门槛。未通过记实验失败并保留基础AA；推荐项未采用要写理由，不伪造成功。
- **MUST，FIFO边界**：网页WebGL/WebView没有可直接选swapchain模式的标准接口，不建立FIFO设置/模块；保持rAF和正确帧节奏。FxPool的FIFO逐出与底层呈现FIFO是不同概念，不互相冒充。
- 现有roundPixels、context antialias参数做A/B；不直接复制像素游戏模板，也不以TAA为由迁移渲染器。

## F. 性能与设置的明确规格

**MUST**：HD4400真实渲染、60Hz前台主测、生产构建；renderer证据、OS/驱动、CPU、内存、浏览器版本、供电和显示输出一起记录。独显/软件渲染/远程工具只可辅助，不能代替。

高级设置：renderScale提供1.0/0.85/0.7（默认1.0）；Bloom强度、反射准确度、粒子细节、环境雾、屏震、减少闪光/动态。低renderScale只在用户选择后生效，报告中注明，不能自动用来通过主目标。

### F3. 自动调节不是允许先掉到40帧

现有 `utils/Quality.ts` 平均FPS<40才收紧且过滤delta>250ms，不能作为本轮稳定60的验收工具。

新监测按真实帧时间：1s滚动窗口，每250ms评估，INIT连续2窗超CPU6ms/GPU10ms成本线时收紧装饰新发射率；连续40窗成本≤CPU4ms/GPU7ms后逐级恢复。GPU不可测时使用CPU＋可见间隔告警，不编造GPU余量。

收紧次序：环境发射率 → 装饰余韵新增量 → 离屏/无贡献光源工作；现存关键粒子自然结束。不得改命中/怪数/敌人AI/危区。结构性RT或shader档切换放安全时点；手动档不擅自降主画质。**自动策略触发说明容量需要复查，不代替T10优化与R14实测通过。**

### G3. 动画 INIT

UI材质首轮使用**离线渲染的几何材质承托图＋DOM清晰文字/输入**：暗材质、左上受光边、粗糙反射与AO按C3同方向制作，承托图打共享小图集；交互局部光由CSS静态渐变/opacity叠层改变。普通hover/按下不触发实时全屏PBR/背景blur。该方式标“烘焙PBR材质承托＋CSS交互近似”，不宣称DOM有实时BRDF；画面风格仍须与世界纵切共同审阅。实时UI材质shader为LATER，不能为了高质量光影给每按钮挂一个filter。

| 动画 | 起始规则 |
|---|---|
| 面板打开 | 220ms，translateY 12→0px、scale 0.97→1、opacity 0→1；曲线cubic-bezier(0.22,1,0.36,1) |
| 面板关闭 | 140ms，位移0→8px、opacity 1→0；关闭意图立即接收 |
| 按钮 | 按下即时scale0.96，释放100ms回1；不改变布局热区 |
| 标签页 | 180ms，8px位移＋opacity，保留共享框位置 |
| Toast | 160ms入场，显示1800ms，140ms退出；同类250ms窗口合并 |
| 可夸张的获得/确认 | 装饰图标250ms scale0.9→1.06→1，正文/热区不跟随放大 |

只动transform/opacity；不默认动画blur、box-shadow、height、width。`prefers-reduced-motion`或设置启用时，位移/回弹关闭，opacity80ms，危险显示仍即时。

可打断：反向关闭/打开从当前视觉值接续；关闭/开页不要求先等动画完成。焦点与输入所有权在操作意图时改变，旧退出画面只保留装饰副本，不接受点击。模态DOM先挂载再渐显防点击穿透，scene暂停采用token且保留真实用户手势。

`UiCommand`携带`requestId`，每次购买/投资/选项原子提交一次；相同id重放不再扣资源。库存/券不足时不先播成功动画。

必须覆盖：Esc、Android返回、关闭按钮、pointercancel、多指、按钮按住期间开模态、关闭模态的pointerup、失焦恢复、设置与事件暂停叠加。根DOM不捕获战斗空区指针，面板捕获自己的操作；列表允许滚动，游戏操作区touch-action按需禁止。

### I1. 文件与服务接口约定（拟建，非现有API）

`VisualEvent`至少有：`eventId/entityId/roomId/runId/kind/phase/worldPosition/height/direction/mode/intensity/startTime/duration/importance`。`worldPosition`来自权威实例，坐标系统由T01定义；事件phase为`start/active/hit/recover/end/cancel`，不能所有命中复用start。

`FxDirector`消费事件并返回表现handle；`FxBudget`只分配装饰/信息配额，不处理伤害。`RenderDirector`拥有当前scene RT；shared静态图集/字体由游戏级资源管理持有。退出room取消room事件，restart取消run事件；不得销毁别的scene共用texture。

`UiSnapshot`只读，`UiCommand`到权威处理入口，`PauseCoordinator`来源token，`InputRouter`一个当前接收宿主。首次改动先定义类型与生命周期单测，再迁移调用，禁止传`any`让第二套状态偷偷成立。

**时钟必须分离**：VisualEvent.startTime来自权威模拟时钟，并记录关联run/room；暂停冻结攻击/危区phase，DOM动效用表现时钟继续。hit-stop期间UI/纯余韵可以推进，但生效危险芯不能先于判定时钟结束。不要统一用performance.now驱动所有危险/粒子/伤害。

**表现RNG迁移注意**：当前`spinSlash()`的火花/余烬寿命仍调用`this.rng.between()`，不能假定所有表现随机已独立。T01列出全部战斗RNG在纯表现热路径的调用，T02使用独立FxRng替换并提交迁移记录。清理污染可能改变旧版本同seed后续序列，不能声称与旧版本完全确定一致；迁移后固定新基线，验证画质/静音/VFX开关不同的同输入模拟结果一致。初次发现结果变化先定位随机流与时序，不默默改测试期望。

**预热清单**：进入战斗前为玩家两特殊、四Boss共用重招、危区mask、SSR/Bloom合成、微粒图集、字体/图标完成加载/解码/上传与shader首编译；报告每项key/variant和预热状态。Boot的超时放行/TextureGuard占位不等于新资产加载正确；缺资源或落占位本次画面验收失败，不能因旧兜底存在就给通过。进房准备切小批CPU工作，shader上传仍在真实渲染上下文完成，不把Worker当GPU上传万能解法。
