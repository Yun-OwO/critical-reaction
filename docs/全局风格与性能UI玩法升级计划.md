## 0. 总体方向与优先级

**一句话方向：暗色反应设施中的精确霓虹几何实体，以清晰的细亮芯、大范围软辉光、逸散粒子云与接地光影，形成干净而有物理层次的 2.5D 化学动作游戏。**

四个目标必须一起成立：

1. **美术统一**：不是把所有物体染成霓虹色，而是统一造型、材质、投影、发光和运动语言。
2. **流畅可信**：HD 4400 实际渲染时，以完整游玩过程稳定 60 帧为硬目标，重点治理尾部帧时间，而非仅提高平均 FPS。
3. **界面服务战斗**：少量核心信息常驻，其余按需展开；桌面和触屏都不裁剪、不遮挡关键操作。
4. **玩法有张力**：动作易上手，构筑与搜打撤有深度；挑战来自可理解、可应对的风险，不靠信息隐藏、磨血或无解随机。

执行优先级：**输入与危险可读性 → 帧节奏与稳定性 → 风格统一和空间层次 → 构筑与内容深度 → 高成本视觉加项。**

### 0.1 与旧计划的关系

本文件是本轮新增需求的主计划，不覆盖历史记录，不把旧计划描述当作当前实现状态。发生冲突时，以本文件的新需求为准：

| 旧方向或旧判断 | 本轮调整 |
|---|---|
| “实体外壳、发光仅辅助” | 主体可以就是无外壳的细辉光几何灯管；实体层次由明暗、遮挡、接地与光照关系建立，不强加装甲壳 |
| “透明几何线框必然有网页感” | 封闭几何、矢量勾线本身就是新风格；应解决线宽、空间关系、同质化动画和亮度失控，而非否定线框 |
| 默认低质量关闭 Bloom | 性能优先档也争取保留风格必需的软辉光；先优化实现、缓冲尺寸和复用，不先删除视觉身份 |
| 地面改成横竖条带 | 保留已修复的 **2:1 菱形晶格**；材质纹理不能再次破坏 2.5D 投影 |
| 音画阶段不改数值 | 本轮允许规划玩法与平衡改进，但美术、性能和数值仍分批实施、分别验收 |
| 像素比例、亮度起伏即可证明美术完成 | 结构测试只能防回归；观感要有真实截图、连续录屏和人工审阅 |

原音频计划中仍适用的语义入口、真实声部预算、手势恢复、分态 BGM、来源授权与试听验收继续保留。本轮不另起一套音频系统。

### 1.2 HD 4400 验收不能用独显代替

本次环境检查发现机器同时有 Intel 集显与 NVIDIA P104-100；`glxinfo -B` 当前返回 **NVIDIA P104-100**。它只说明桌面 OpenGL 状态，甚至不能直接说明浏览器实际使用哪个 GPU。

后续性能验收必须：

- 在用户确认的 HD 4400 环境运行；记录 CPU、内存、驱动、浏览器/WebView 版本、供电、显示器刷新率和分辨率。
- 核对浏览器 GPU 页面与 WebGL renderer；调试扩展可用时记录 renderer 字符串，不可用时补充系统与浏览器证据。
- 明确排除 P104-100、软件渲染器或远程浏览器结果冒充 HD 4400 实测。
- 切换 GPU/驱动属于后续需授权的环境操作；**本次不切换、不禁用独显、不改启动参数。**
- 软件限速、CPU throttling 只能做辅助压测，不能模拟集显带宽、驱动和热状态。

## 2. 全局美术规范：霓虹几何 × 有物理依据的层次

### 2.1 造型语法

1. **封闭图形为主体**：三角形、菱形、矩形、凸多边形和正圆；转角明确，避免任意圆角胶囊、复杂有机外壳和手绘毛边。
2. **通常一个主体**：一个主轮廓决定身份，最多少量次级闭合图形叠加，表达防护、储能或催化；不把多个同等亮度图标拼成一团。
3. **边与圆都精确**：光芯连续、线宽稳定、几何对齐；造型不靠每帧高细分 Graphics 重描。
4. **叠加要有空间理由**：前后层、嵌套深度、遮挡或接地高度可被读出；不是无理由同心圆堆叠。
5. **无外壳的灯管感**：薄亮芯＋窄彩色光带＋大范围低强度柔辉光；不画厚重黑壳或塑料按钮边。
6. **少而准的区别**：敌人角色通过主图形、朝向、内部遮挡结构、启动动作区分，颜色只是辅助。

**必要例外**：文字笔画、激光路径、运动拖尾、现有电子轨迹、危险指向线可以开放；真实机制环/圆形范围可以保留。贴地正圆在等距投影中会呈椭圆，投影阴影也可为椭圆——不能为“只用正圆”而破坏投影。粒子光雾的软边不属于实体造型边界。

### 2.2 材质分工：不要混淆风格与算法

“矢量感”约束轮廓与图案；“PBR 写实质感”约束光照、反射、粗糙度、遮挡与接地。这两者可以结合，但不是“给 SVG 加渐变就等于 PBR”。

| 材质族 | 形态与用途 | 光影规范 |
|---|---|---|
| 自发光几何 | 玩家、活性敌人、武器能量、核心信号 | 发光芯不被暗面吞没；彩色辉光与自身主形分层；AO 不应把发光本体涂黑 |
| 哑光暗底 | 墙、绝缘体、障碍暗面、UI 承托 | 低明度，柔和接触阴影；不是全黑，也不抢霓虹亮度 |
| 微粗糙反射面 | 地板、终端、局部金属面 | 有模糊、衰减、方向正确的反射；不把所有表面做成镜子 |
| 透明介质 | 样本容器、薄隔板、局部 UI 层 | 局部反射和边缘高光，保持后景可辨；不铺满全屏玻璃模糊 |

基础档目标是**PBR 观感与一致材质响应**。少数关键表面可尝试法线/粗糙度驱动的实际光照；整套精灵的物理 BRDF、完整延迟管线与 HDR 不作为未经验证的默认承诺。

### 2.3 配色、曝光与信息优先级

候选色令牌（待纵切校准，不直接覆盖现有氧化/还原语义）：

| 角色 | 候选色 | 使用约束 |
|---|---|---|
| 深背景 | `#070B14` / `#101726` | 暗但仍看得见通道、地物高度和材质变化 |
| 亮芯 | `#EAFBFF` | 少量接近白色；高亮后仍保留彩色外缘，不全画面过曝 |
| 活性青 | `#45E8FF` | 玩家/友方或交互强调，最终按既有语义分配 |
| 霓虹紫 | `#B07CFF` | 特殊反应/稀有强调；不与危险混用 |
| 洋红 | `#FF4BBD` | 独立功能强调；限制同屏大面积使用 |
| 危险橙红 | `#FF6A4D` | 危险/受伤语义保持连续，不随染色换成安全色 |
| 可读正文 | `#DBE7F3` / `#A5B7CA` | 文本不依赖 Bloom 提亮 |

- 主体高明度、背景低明度，**高对比不是所有内容都最亮**。
- 信息顺序：致命危险与玩家位置 → 有效弹道/敌人意图 → 交互出口 → 收益与状态 → 环境装饰。
- 染料改变能量色和局部材质，不覆盖敌我识别边、危险预警或血量语义。
- 灰度图与色觉模拟下仍有区分度；敌我、危险/安全不能只靠红绿差异。
- 大 Bloom 不等于大片白雾：留黑位、彩色过渡和清晰芯；密集叠加使用亮度软压缩，避免硬截成白板。
- SDR 显示器也应成立。线性光叠加、sRGB 输出与预乘 alpha 需统一验证，不混合重复 gamma 校正。

### 2.4 精灵纹理与 2.5D 层次

以“主轮廓 → 明暗面 → 遮挡 → 克制直线排线 → 辉光”制作，细节不能逆转主体身份：

- 明暗面采用清楚、平整的几何分区，亮面窄而突出，暗面均匀；不增加大量随机噪点。
- 直线排线是阴影材质语言：方向统一、低对比、间距经过目标尺寸校准；不画成抢眼的第二套地图网格。
- 小尺寸用烘焙后的暗面/排线，远景减淡高频纹理；检查亚像素闪烁和摩尔纹。
- 主体内部叠加用遮挡建立前后关系；外部通过脚点、高度、接触阴影、局部反射和雾前后分层建立空间。
- 圆形主体不可在动作中随意拉伸成椭圆；反馈优先局部发光、内层位移、刚体偏转和粒子释放。
- 地板仍为 2:1 菱形格栅；格内材质沿等距轴投影，阻挡侧壁必须源自真实 `collidable`。
- 高但可通过的装饰不得画成实心阻挡；所有升起效果核对高度与脚点，防止视觉碰撞不一致。
- 不用植物、花草或与化学设施无关的写实杂物填充环境。

### 2.5 资产制作与交付

- SVG 保留为原稿；运行时优先加载预栅格化并打图集的精灵，不在战斗时解析/重绘复杂矢量。
- 主体/暗面可以合并烘焙；emissive、必要的法线与材质 mask 按用途独立，不默认每个物体都带全套贴图。
- 图集预留 gutter、透明边与辉光外扩，检查线性采样和 mip 边缘；不把辉光剪到精灵矩形边。
- 线宽按最终 CSS 可见尺寸校准，而不是只看源 SVG 的 stroke 数值。
- 每项记录 source、生成参数、hash、许可、用途与替换关系；不能因参考工程开源就认定其中字体/音画均可分发。
- 首批先制作玩家、一个近战敌人、一个射线敌人、一个障碍、一块地面、一个交互终端；通过后再覆盖现有 8 类敌人与 4 个 Boss。

## 3. 特效规范：密度驱动的逸散光雾

### 3.1 目标形态

借鉴《奇异博士》效果的**能量聚集、局部涡旋、粒子破散、明暗密度与空间遮挡**，不照搬魔法阵、角色图案和大片圆环。

主要效果由大量微小自发光粒子组成：近处有可辨颗粒，中距离融合为柔和云雾；叠加处更亮、更浓，稀疏区自然变淡，外缘完全透明。不是一个完整贴图沿固定路线匀速移动或单纯缩放。

### 3.2 运动与透明规则

1. **发射有原因**：攻击接触、电子转移、裂解、喷口、泄漏是源；没有事件就不持续发满预算。
2. **空间相关的随机**：初速、寿命、尺寸有小幅分布，叠加共享低频扰动场；不能每帧独立随机改方向而抖成白噪声。
3. **流体感而非真实流体求解**：阻力、卷吸、浮升、局部涡流和源速度共同影响。先试 CPU 采样共享噪声场，不默认给每粒子做多次昂贵噪声计算。
4. **无固定重复路径**：同类事件保持身份，但形态不完全相同；表现 RNG 与战斗 RNG 分离，画质切换和静音不改变战局。
5. **密度决定浓淡**：软核权重随半径平滑衰减到 0，透明边外留 padding；寿命淡入/淡出自然，不能突然切掉矩形或整团消失。
6. **色彩能量可加，alpha 要正确**：在共享低分辨率场累计密度 `D` 与发光 `E`，可用 `alpha = 1 - exp(-kD)` 作浓度映射；该公式只是设计模型，不宣称完整参与介质物理。
7. **防 LDR 饱和**：若使用 RGBA8 密度/发光场，预缩放、限定范围并测试编码精度；不能先把密度截断再靠 Bloom 伪装云层。半浮点缓冲必须先测支持与成本，非默认依赖。
8. **云与粒子同源**：低分辨率云场由同一批微粒软核积累，清晰微粒另在主画面小面积绘制；不是新增几张巨型云雾 billboard。

### 3.3 事件表现模板

| 事件 | 主表现 | 不采用的捷径 |
|---|---|---|
| 光剑命中 | 接触点短亮芯、方向性微粒、局部卷散余雾 | 每次都放同样的大圆环或整块扇形发光贴图 |
| 反应炮发射/命中 | 喷口聚能、可读弹道芯、接触后密度爆散 | 全程巨球、全屏模糊或固定比例膨胀 |
| 冲刺 | 短段微粒逸散，保留玩家位置与起止点 | 长寿命实心残影占满路径 |
| 氧化/还原 | 破散/收聚的趋势区别，电子仍可读 | 靠改色宣称两套表现，或运动完全照搬 |
| 普通死亡 | 主几何熄灭、局部裂散、短余韵 | 所有小怪都使用 Boss 级爆炸 |
| Boss/撤离 | 集中能量＋有限宽光束＋分层雾 | 一律增加粒子数量、白闪时间和全屏覆盖 |

危险范围、机制轨道和必要的激光芯**不受“减少环形/整体图案”的装饰限制**，须始终明确。软雾是气氛与反馈，不能替代准确攻击边界。

### 3.4 粒子性能策略

- 延续共享池，热路径零/低分配；预热最大常用量，池实际分配量和活跃量都计入预算。
- 预算同时覆盖活跃粒子、每秒发射、屏幕覆盖面积、混合次数和缓冲 pass，而非只限制数量。
- 危险/命中保留额度，先拒绝环境装饰，再削减余韵；现有 FIFO 淘汰不能直接把重要命中粒子全部挤掉。
- 装饰缩减采用平滑的发射率调整；已有粒子自然结束，不在一次帧尖峰后整片消失。
- 粒子池即使复用对象，仍可能有 display list、遍历和 draw-call 成本；必须用 profile 证明，不把“池化”写成“无成本”。

## 4. 光影与渲染技术路线

### 4.1 同一画面，不盲目堆后处理

建议渐进形成以下逻辑顺序，开发时据 Phaser 4.2.1 的 render node/filter 实际能力决定如何合并，**不是承诺每项都独立全屏 pass**：

```text
房间静态底层/材质缓存
  → 地面局部反射 + 接触遮挡
  → 按脚点/高度排序的主体、障碍与暗面
  → 清晰弹道与亮芯
  → 前后分层的小粒子/光雾/有限光束
  → 共享近/远尺度 Bloom 与曝光合成
  → 不经重模糊的关键危险提示
  → Phaser 高频触控层 + DOM HUD/菜单
```

辅助 height/normal/material mask 与实体数据同源；固定脚点和高度映射，禁止直接把 Phaser 的排序 `depth` 当作相机线性深度。反射、阴影与 fog occlusion 必须使用相同的世界到屏幕变换。

### 4.2 Bloom：强效果、低采样成本

- 优先让需要发光的内容进入共享 emissive 场，避免当前低阈值把背景和一切文本都提亮。
- 亮芯保持主画面分辨率；窄辉光可烘焙，宽辉光通过低分辨率模糊形成。
- 候选近/远尺度为主画面 **1/2、1/4、1/8 的宽高**，先试两级再决定是否加第三级；不是“分辨率面积减一半”。
- 比较少量可分离 blur 与双滤波下/上采样；用最终观感与 GPU 帧时间选型，不以算法名称决定高级感。
- 同帧复用发光/光雾缓冲，避免每个角色独立 Blur/Glow filter；静态灯光直接缓存。
- 给宽范围辉光更多半径与层次，不必给更多 blurSteps；避免屏幕角落和图集边界硬切。
- 关键线、预警、正文不被后处理糊掉；任何滤镜设置都不能让危险消失。

### 4.3 多层屏幕空间反射：基础方案与真实 SSR 分开验收

**视觉目标**：贴地近反射较清晰，远反射更模糊、更淡；灯光和运动主体在局部反射面上产生一致的空间响应，而非统一倒影复制。

**推荐基础方案：受限地面反射合成。**

- 只对有反射材质的地面/终端表面工作，以物体脚点、离地高度和固定观察方向投射，不把整张画面上下翻转。
- 共享低分辨率反射源；用粗糙度 mask、距离衰减、地面可见区域与遮挡 mask 合成近/中/远层。
- 模糊层可重用 mip/降采样结果；静态反射缓存，运动反射每帧更新，不能给移动主体 10–15 Hz 的明显滞后倒影。
- 不反射 HUD、预警、无物理表面的离散光尘；能量在不可信反射边缘平滑消退。
- 此方案是 **2.5D 平面/材质近似反射**，不是基于深度射线步进的真实 SSR。文档与设置不能冒名。

**真实 SSR 的独立可行性切片：**

- 需要一致的屏幕空间深度、法线、材质和命中厚度；半透明发光精灵必须与实体几何区分。
- 先在单个反射表面、低分辨率和有限射线步数中验证；记录漏光、离屏失效、遮挡错误和 shader 编译尖峰。
- 单位排序值、描边 alpha 和颜色亮度不能伪造完整 G-buffer。
- 在 HD 4400 上不能满足预算时，不默认上线真实 SSR；明确提交“目标观感由近似实现、算法项未达成”的评审结果。若必须以真实 SSR 为验收条件，需重新审阅架构/成本，不能悄悄替换。

### 4.4 环境光遮蔽与 PBR 材质

- 基础路径：房间生成时缓存墙脚、障碍接触、凹角 AO；移动主体使用小面积接触阴影/遮蔽 mask。
- 接触阴影使用 NORMAL/MULTIPLY 等合适方式合成，审计现有 ADD 阴影；不得把黑色 ADD 误认为能压暗地面。
- AO 压暗受光不足的非发光表面，不无差别压暗灯芯；强发光造成的邻近受光应另行处理。
- 少量关键地面/终端试验法线＋粗糙度＋统一环境光；Phaser 的 ImageLight 是候选 IBL 手段，**它不等于完整 PBR/SSAO/SSR**，须对照本地 API 与材质能力。
- 真实 SSAO 同样依赖深度/法线与采样；只有测得有益且在预算内才扩展。接触 AO、烘焙 AO、height-field AO 分别命名，不混称 SSAO。

### 4.5 光束、激光、体积雾与模糊

- 激光用精确中心线/危险边界＋软横截面光能＋局部微粒，不依赖宽实心矩形表达全部效果。
- 体积感优先来自前后雾层、受遮挡的定向散射、小粒子密度与接地光，不默认为全屏三维 raymarch。
- 环境光束限制包围区域、长度和同屏数量；粗糙噪声共享，避开玩家和预警关键区域。
- 模糊主要作用于辉光、粗糙反射和软雾；主场景、字、危区不作常态高模糊。运动模糊非首批默认项。
- 近似光束/雾不宣称真实体积光，若后续做深度感知散射，独立标记算法与验收状态。

### 4.6 TAA、FIFO 与抗锯齿选择

| 技术 | 实际要求/限制 | 本计划决策 |
|---|---|---|
| TAA | 历史颜色、投影抖动、运动矢量、重投影、遮挡剔除/裁剪；细亮线和透明粒子容易鬼影、变糊 | **不设为首批默认**。先验证字体之外的世界细线运动；有完整运动/深度数据和性能余量后再做小样，与非时间方案 A/B |
| 基础 AA | 纹理预滤波、边缘 padding、采样/缩放、必要的解析 coverage、浏览器 context AA | 优先保障矢量线与圆清晰稳定；context AA 不能自动解决所有透明精灵/纹理边缘问题 |
| FXAA/形态 AA | 额外采样，可能误伤亮线和 UI | 单个世界合成 pass 可选试验，正文与 DOM 不经过该 pass |
| FIFO | Vulkan 等底层 swapchain 呈现模式，不是抗锯齿，也不是提高吞吐量的魔法 | Phaser WebGL/Capacitor WebView 无直接选择 API；不添加假 FIFO 开关 |
| rAF/帧节奏 | 浏览器按刷新调度，呈现由浏览器/合成器管理；隐藏页通常暂停 | 保持 rAF，防止双循环、定时器抢跑、积压输入与无限补帧；高刷屏验证 60 帧节奏 |

“较现代化”应以质量、延迟、尾帧和可维护性证明。TAA/FIFO 不因名字新就优于当前工程适配的方案；不为了实现它们擅自更换引擎。

## 5. 性能工程：先减少无效工作，再谈画质取舍

### 5.1 稳定 60 帧的定义与证据

60 Hz 下每帧约 16.67 ms。平均 60 FPS 不能证明没有低帧；JS 提交耗时也不能证明 GPU/合成呈现没有掉帧。

后续验收同时记录：

- rAF 帧间隔、CPU update/render-submit 时长、长任务、GC、资源上传/编译时段。
- GPU timer 扩展可用时异步采样 GPU 耗时，并处理 disjoint；不可用时用浏览器 trace/实际呈现录制和受控对照补证，不强制同步 `readPixels`。
- 主体/粒子/弹道数、draw calls、纹理切换、RT 尺寸/占用、反射/Bloom pass、DOM layout/paint/composite。
- P50/P95/P99/P99.9 帧时间、1%/0.1% low、超过预算次数与最长卡顿，并定位发生的操作。
- 1% low 定义为最慢 1% 帧间隔的均值取倒数，0.1% 同理；不要用单个 percentile 倒数混充另一种算法。

**项目验收目标（非本轮测量结果）：**

| 指标 | 拟定门槛 |
|---|---|
| 正常游戏与菜单转场 | 目标 60 FPS，1% low ≥59、0.1% low ≥58；仅容许测量/调度微抖，不代表接受持续低帧，不能靠降低模拟速度达成 |
| CPU 热路径 | P95 ≤6 ms，重点排除分配/同步调用尖峰 |
| GPU 工作 | P95 ≤10 ms，整帧尽量留 3–4 ms 余量；CPU/GPU可重叠，不能机械相加当作实测整帧 |
| 可见帧间隔 | P99 ≤18 ms；明显错过一轮刷新（例如 >25 ms）全部统计，项目可归因次数目标为0，不允许重复突发 |
| 项目导致的顿卡 | 稳态游玩中 ≥33.3 ms 的项目可归因尖峰为 0；Boss、换房、开面板不能另行免责 |
| 热稳定与持续性 | 预热后连续 30 分钟，常用菜单往返与最重战斗可重复通过，不只测开局 |

上述统计允许刷新时钟微抖，不允许用“平均值符合”掩盖 low 帧。门槛未达到就标未通过；若需修改门槛/目标分辨率，必须明确提出。

浏览器调度、系统抢占、驱动或其他应用可能造成不可控制的停顿，不能诚实承诺“任何环境永不掉一帧”。工程目标是消除项目内可控尖峰，并在约定 HD 4400 环境实测达到上述门槛；如实记录外部异常，不删除不利样本。

### 5.2 优化顺序

1. **先测基线**：确认 CPU、GPU、透明填充、物理或 DOM 的主瓶颈；同 seed/同输入轨迹、同数量、同分辨率对照。
2. **资源与 shader 预热**：Boot/安全间隙内预加载、解码、上传常用图集和预编译候选 shader；首次 Boss/面板/连锁不能现用现建。
3. **剔除和缓存**：静态房间分块缓存、dirty 更新、相机外视觉剔除；TileSprite 菱形网格保留。视觉剔除不能跳过必要模拟/碰撞。
4. **减少提交与状态切换**：图集、同材质批次、共享滤镜缓冲、预计算几何；同时保住前后遮挡顺序，不为 batch 任意重排透明层。
5. **处理 CPU 热路径**：敌人/弹道空间查询、物理 broadphase、事件合并、浮字复用、缓存属性推导、按需更新 UI；移除重复监听和生命周期泄漏。
6. **压透明过绘制**：微粒小包围区域、密度场统一合成、辉光共享、遮罩裁域；优先省无用透明像素，不先砍效果数量。
7. **调度非紧急工作**：房间准备、列表计算和存档序列化切分；仅纯数据重任务适合 Worker，不能把 DOM/Phaser 场景直接搬进去。
8. **再试不同算法/分辨率**：共享低分辨率特效、短 pass、AO缓存、分层反射；主画面降采样放最后，需证明观感可接受。

不使用 `gl.finish`、每帧同步 GPU 查询或强制 GC“解决”卡顿；不通过减少敌人、改变判定、随机丢攻击实现不同画质档的帧率。

### 5.3 初始预算与设置架构

预算仅为开发起点，P0 基线后再锁定，不能把它写成已验证的 HD 4400 容量：

| 项 | 性能优先候选预算 | 策略 |
|---|---|---|
| 主画面 | 首先测 1280×720 与当前 1920 长边；逻辑视野相同 | 不预先判定必须降分辨率；分别报告两种结果，最终目标需明确 |
| 软光/云场 | 1/4 宽高，必要近场 1/2 | 核心细线保持清晰，后处理只影响软层 |
| 同时活跃微粒 | 起始 400–800，关键事件保留约 25% 配额 | 以屏幕覆盖/CPU实测调整；共享云场维持视觉密度，不保证这些数字能达标 |
| 动态受光热点 | 起始 2–4 个关键局部源 | 按材质与视野选取，环境灯预烘焙 |
| 额外 RT 内存 | 性能档目标 ≤32 MiB | 统计实际尺寸/格式/复用、深度/多采样附件；不只算单张颜色纹理 |
| 常用图集纹理 | 起始目标 ≤64 MiB | 1024/2048 图集优先；解码后与 mip 占用另计，不用压缩文件大小代表 GPU 内存 |
| 可见世界 draw calls | 目标起始 ≤100 | 是告警线，不是 60 帧保证；需同时看像素、状态切换、shader 成本 |
| 战斗 DOM 更新 | 普通读数约 10 Hz/值变更触发；危险和受伤立即更新 | 动画由合成层推进，不在每帧重建整棵 DOM |

例如 RGBA8 的 1280×720 单纹理约 3.52 MiB，1920×1080 约 7.91 MiB；多套全尺寸 ping-pong 很快耗尽预算。这是内存估算，不等于带宽/帧率测量。

设置采用“推荐预设＋高级选项”，不能再只靠 touch/核数推断质量：

- **性能优先**：保留亮芯、大范围软光、接触 AO、受限反射和逸散云形；较小软层缓冲、静态复用、少量动态光。
- **均衡**：在相同艺术语言下提高软层解析度、反射细节、局部动态材质与雾层。
- **精细**：提高材质/反射准确度；真实 SSR/SSAO 只有可行性验证通过后才可能出现，不能列为现成能力。
- 高级项：主画面 render scale、辉光强度/解析度、反射路径、阴影/AO、粒子细节、环境雾、抗锯齿、屏震、减少动态效果。
- 风格强度与计算质量分开：降低 blur 解析度不必降低用户设置的霓虹强度；但须校准重建后亮度，防止不同档变成不同画风。
- 自动调整先动不可见工作与装饰采样，使用滑动窗口/迟滞；不因单个坏帧频繁改变 RT 尺寸。RT 预分配，结构性切换放安全时点。
- 手动档不静默降主画面清晰度；开启自动调整时展示其允许范围。不存在假 TAA/FIFO 或“30 帧也算稳定60”选项。

### 5.4 物理和时序专项

- 对比 120 Hz 物理的真实收益与成本：高速冲刺、薄障碍、密集碰撞、电子转移时机必须回归。
- 若采用 60 Hz 固定模拟＋表现插值，需另补高速扫掠/子步保证；不能直接降低物理频率制造穿透。
- 插值仅用于显示，不用插值坐标作权威判定；输入反馈不得因缓冲多等一帧而钝化。
- 补帧设上限并记录超限；不积累无限子步形成 spiral of death，也不能悄悄跳过关键判定。
- 重新 A/B `roundPixels`：矢量勾线和平滑相机可能更怕整像素跳动，不默认它能消除所有残影。
- hit-stop 是设计中的局部定格，不应停止浏览器渲染、UI动效和输入读取；分析时与真实卡顿分开标记，二者都不能遮蔽低帧统计。

## 6. UI：混合架构、几何光影与渐进信息

### 6.1 信息层级与界面归属

| 层级 | 内容 | 默认行为 |
|---|---|---|
| 一级：战斗关键 | 生命/防护、温度危险、当前武器/模式、关键资源、冲刺就绪、撤离方向 | 紧凑常驻，以图标/短数字/状态条为主 |
| 二级：上下文 | 可交互终端、奖励、购买结果、临界警报 | 靠近时或事件发生时出现；非紧急信息柔和入场，危险立即可读 |
| 三级：构筑详情 | 祝福、遗物、染料配比、词条推导、经济明细、完整路线 | 从明确的二级入口展开，不一上来全屏铺开 |
| 局外管理 | 装备/遗物/进化/投资/设置 | 分组页签与就地详情；一个主任务、一个清楚返回路径 |

推荐分工：

- **Phaser**：世界内标签/预警、高频触控摇杆和战斗输入；先保留工作正常的控件，避免一次迁移全部高频输入。
- **DOM/CSS**：大厅、商店、事件、祝福、结算、设置；逐步让屏幕 HUD 使用清晰的本地字体和 CSS 布局。
- **共享契约**：UI 只发语义命令、读只读快照；不导入第二个 GameState 模块实例，不直接改场景内部对象。
- **表现光层**：需要真实材质响应的少量面板可用缓存纹理/共享 shader 试验；普通按钮用 CSS 明暗边、反射渐变和小范围光，不每个按钮单独全屏 WebGL滤镜。

CSS 可做材质近似，不具备完整场景 PBR。若某 UI 采用烘焙/PBR渲染背景，仍将清晰文本与可访问交互保留在 DOM；不可用模糊光影换难读字。

### 6.2 拟建的状态与输入桥

```text
游戏判定/状态 → UiSnapshot / 状态变更事件 → DOM 或 Phaser View
鼠标/键盘/触摸 → UiCommand → 权威处理 → 一次性结果 → 反馈/视图
                 PauseCoordinator / InputRouter 管理所有输入与暂停权
```

- 同一购买/投资/选择按事务 ID 去重，动画期间重复点击不能重复扣费。
- 暂停使用带来源的 token；事件、设置、失焦分别释放自己的 token，关闭一个面板不能解除另一个暂停原因。
- UI 模态打开时清空/拦截战斗攻击缓冲；关闭后的同一次 pointerup 不触发穿透攻击。
- DOM 根层 `pointer-events: none`，交互面板/按钮局部启用；热键、鼠标与触摸只能路由到一个宿主。
- 关闭要处理 pointercancel、长按、失焦、多指、Android 返回键与 Esc；只对游戏操作区禁用浏览器手势，不一刀切禁止所有列表滚动。
- Scene shutdown/restart 清理监听、动画和订阅；正常 Boot 完整加载，不能靠强启场景验证。

### 6.3 视觉组件

- 封闭矩形/切角多边形/正圆为结构；不采用厚圆角卡片瀑布与大面积网页渐变按钮。
- 暗底板＋一条明确受光边＋小范围反射＋稳定正文形成主次；hover/选中亮起，不所有组件常亮。
- 一级 HUD 只留下必要状态，详情通过图标＋短标签、点击/快捷键二级展开；关键规则不能为了少文字被隐藏。
- 祝福候选默认“名称＋一句作用＋关键变化”，展开显示公式、触发和两武器适配；不需要读一大段才能判断损失。
- 危险状态有形状/图标变化和必要的准确数字；普通收益信息合并，不让浮字/提示遮住敌人。
- UI 光影方向与场景统一；大 `backdrop-filter`、持续扫描线、全屏 blur 和多重动态 box-shadow 非默认基础。
- 常规面板保留战场上下文，操作区与战斗中心分离；标题/加载/明确结算可使用独立画面，但不能把全屏弹窗作为所有操作的默认方式。

建议布局起点：PC常规管理/选择面板宽度上限约640–800 CSS px、可用高度上限约80%；移动端上限按安全区内可用宽高计算，不依赖固定放大倍率。战斗中心保留约60%宽×55%高的优先无遮挡区域，常驻信息尽量沿边组织；这些是布局调试值，不代替小屏逐界面验证。

### 6.4 动效：丝滑、可打断、不延迟操作

初始节奏供纵切调试：

| 动作 | 候选时长/幅度 | 规则 |
|---|---|---|
| 按下反馈 | 下一可渲染帧内，约 80–120 ms 回弹 | 状态立即生效；只有装饰回弹，不等待动画才响应 |
| 普通面板入场 | 180–260 ms，8–16 CSS px 位移，约 0.97→1 缩放 | 有起落，不从屏外飞很远；屏幕边界不因放大被裁剪 |
| 关闭 | 120–180 ms | 可中断/反向，不能等长动画才允许退出 |
| 页签/详情切换 | 160–220 ms，共用元素连续转移 | 不重建整个页面、闪白或反复触发布局 |
| 非危险 toast | 120–180 ms 入场，短停留后消散 | 合并同类，位置避开控制区 |
| 危险提示 | 即时建立可读主形，装饰随后过渡 | 不能“丝滑淡入”到最后才看见攻击范围 |

- 借鉴苹果式连续动量、共享元素与轻微回弹，不照搬圆角/模糊玻璃/长时动画。
- 热动效只动 transform/opacity；阴影、blur、clip-path、尺寸在低配上可能触发重绘，先测再用，禁止 `transition: all`。
- 不把每个 DOM 元素都永久 `will-change`；限制合成层数量与纹理占用。
- 使用固定曲线或可控阻尼动画；动画被打断从当前状态继续，不突然跳终点/起点。
- hit-stop 或暂停期间 UI 仍平滑；尊重 `prefers-reduced-motion` 和游戏内减少动态效果设置，关闭回弹/长位移，不牺牲关键信息。

### 6.5 PC、移动端和小屏约束

- 布局以 **实际 CSS 视口**、canvas 可见矩形、`visualViewport`、安全区为准；几何缩放、字号和输入热区分开。
- 触控目标至少 44×44 CSS px，常用战斗按钮建议 ≥48×48，邻近目标留明显间距；视觉图形可小于热区。
- 字体以 CSS 字号上下限和行高管理，不跟 1920 内部画布等比暴涨；正文建议 14–16 px，极短次级标签可更小但必须实读验证。
- 面板使用 `min(上限, 可用宽度)`，高度以可用区域减安全边距为界；标题、返回/关闭和确认区保持可见，列表内滚动。
- 不用裁剪内容/字号无限缩小解决溢出；窄屏减少同时展示的列数，三级详情另开。
- 横屏 20:9 左右控件不外溢；4:3/16:9 和竖屏重新布局，不直接压扁横屏。极窄竖屏采用渐进页签/可滚动详情，不假设旋转提示等于竖屏已适配。
- 摇杆与攻击按钮支持多指；手指占用区域不得覆盖撤离、暂停或关闭按钮。
- 键盘提供可见焦点、Tab 导航、1/2/3 快选、Esc/返回；不能要求 hover 才有说明，手机用点击展开。
- Android 返回键先关闭子页/面板，再处理暂停/退出；确认退出必须可取消，不与页面后退混用。

### 6.6 内置资源与体验一致性

- 候选中文字体为具有可分发许可的思源黑体/Noto Sans CJK，采用必要字重的 WOFF2 分包；数字单独设置 tabular-nums，必要时内置数字字体。
- 字体、图标、提示音本地打包，无运行时外部 CDN 依赖；保留许可和来源登记。
- 核心 UI 字符预载，完整动态文本有覆盖兜底；游戏 HUD 如使用 Canvas 文本，必须等本地字体就绪再创建/重绘。
- 不把 Emoji 当关键图标，以免设备字形/颜色不一致；使用统一的自制几何 SVG 图标。
- 检查首次加载、离线启动、缓存更新和缺字；字体加载前后不得改变按钮位置或导致文本溢出。

## 7. 玩法、平衡与氛围：参考方法而非换皮

### 7.1 三个参考的具体借鉴

| 参考 | 机制/工程事实与方法 | 本作转译 | 不照搬 |

| 明日方舟集成战略 | 招募券类型＋希望构成受约束的选择；路径事件、收藏品、商店与跨局投资产生长期规划；不同主题的投资规则/门槛不同 | 可见路线奖励、有限资源购买/投资、事件收益代价、遗物联动、分组信息界面 | 干员阵容/职业招募、庞大物品总量、刷投资或隐藏坏事件的疲劳 |

集成战略的“简约 UI”或参考工程“看起来流畅”不构成本作性能证据。《奇异博士》是特效形态参考，不是性能或玩法模板。

### 7.2 核心循环与节奏

保留并强化：**选两武器与起始配置 → 看路线选择风险 → 交战/搜集 → 购买或投资 → 形成构筑 → 主动控温 → 继续深入或撤离 → 带回样本与解锁 → 下局换打法。**

- 建议先做 15–25 分钟标准完整局的体验样本，单个常规战斗房约 30–60 秒；这是调试目标，不强制所有战斗按计时结束。
- 早期一房教一件事：移动/预警、氧化夺取、还原控温、两武器互补、撤离判断，避免第一分钟读多个系统说明。
- 房间节奏“建立目标 → 压力峰值 → 可读收尾 → 短补给/选择”；同屏视觉负荷与敌人组合一并预算。
- 非战斗房降低环境威胁与音画强度，让选择可以思考；不要玩家读事件文案时继续因未明示规则被烧死。
- 提前撤离是完整策略，不是“失败的通关”；与深入收益之间有清楚的风险差异。

### 7.3 先审查现有反体验规则

| 当前规则/风险 | 为什么要审查 | 拟定处理方向 |
|---|---|---|
| `applyPacingHeat()` 按清房快慢升温，快者可从 4°逼近18° | 可能惩罚好操作，鼓励拖时间等温度收益；UI不解释时像暗中加难度 | 优先改为玩家可见、可选的热压挑战/风险房；若保留自适应，提前说明且不削弱高效操作的净收益 |
| `runawayCancelThreshold` 等整击取消 | 堆强后突然零收益，容易形成“越升级越差”的隐藏门槛 | 比较明确的容量溢出/边际递减/可预览副作用；必须让升级前后效果可计算，不贸然改成另一隐蔽惩罚 |
| `runDisabledCount=2` 局内禁用祝福 | 随机禁用可能切断想玩流派，而不是增加决策 | 审查禁用池、提示时点和核心组件保底；不按手持武器过滤祝福、不让禁用导致无解构筑 |
| 进化有 `hpMult`/暴伤等属性，部分目前只见计算/描述线索 | 显示变强却不影响真实战斗会破坏信任 | 做全属性“来源→快照→判定→UI”对账，测试真实 HP 上限/暴击伤害，而非只测纯函数 |
| 投资 reserve 上限120，但图鉴门槛至880 | 储备余额与累计投资是否独立、有无持续入口及持久化需查；不能靠表格认定可达 | 明确累计额/余额/解锁三个字段及应用链，端到端证明所有目标可达；本次不凭单文件宣判整个系统已坏 |
| `sp-ledger` 描述“投资不再占用局内券” | 可能消除最关键的局内/局外取舍，甚至凭空套利 | 改为更便利但仍有成本的结算分配候选；先经济建模，再决定是否换效果 |
| 事件以 flags 表达卖装备等结果 | 纯函数返回不代表库存真的减少；支付、奖励可能未完整同一事务应用 | 核对全部选项实际后果、退出、重复点击、存档恢复；禁止无限购卖套利 |

“不恶心”不意味着取消所有限制；任何代价都要可见、可预期、有选择或有可练习解法。

### 7.4 两武器与构筑深度

- 每局始终两武器，近/远互补和切换时机是深度，不再叠一排战斗按键。
- 先为现有光剑/反应炮制作少量动作行为变体，如命中节奏、弹道形态、控场/转移倾向；具体效果仍需策划审阅与技能接线测试。
- 不按武器过滤祝福池；每个祝福展示当前手持两武器的分类作用，通用/光剑/反应炮/状态收益清楚标识。
- 对不直接作用于某武器的祝福，清楚说明作用对象；不能文案假称双方获益，也不能悄悄改变既定抽池要求。
- 首轮至少验证三种完整构筑：氧化爆发、还原控温、切换循环；后续再考虑粒子/射线、护盾反应、染料纯化等分支。
- 每条流派应有起效组件、转换组件、风险成本和补救组件，不只堆“伤害＋X%”。普通选择也能组成可玩的局，不能必须抽中传说核心才有乐趣。
- 新武器先数据驱动武器行为与升级接缝，再扩到其他武器；新武器交易用“替换两槽之一”而非额外永久加槽。
- 保留已规划的多人联机输入/快照接缝，但本轮不实现联网；表现系统依赖事件 ID/实体 ID，不直接决定模拟。

首轮构筑验证样本（效果是候选，不是本次新增技能，也不假设新建独立资源槽）：

| 流派 | 起效与转换方向 | 必须保留的决策 | 防无脑/防枯燥验证 |
|---|---|---|---|
| 氧化爆发 | 有效电子夺取支持更强的现有特殊攻击；以光剑近身或反应炮点杀兑现 | 留自由电子应急，还是立刻爆发；继续输出还是切还原控温 | 不能永久免费连爆；不允许输出升级后暗中零伤；冷却期间仍有有效普攻 |
| 还原控温 | 有效注入换取温度回落、有限防护或战斗节奏优势 | 安全降温与直接击杀的机会成本；何时转回氧化收尾 | 不能无限刷盾/无限冷却；防御路线不能靠长时间磨血才可过关 |
| 切换循环 | 两武器/两态互补，正常有效命中推进短期协同收益 | 何时切换才能利用射程/恢复窗口，而不是机械按键轮换 | 不靠空挥/原地切换刷收益；不要求手机同时按多个键；单武器短时坚持也不立即失去生存能力 |

每条都验证“普通核心可成型、两个不同补强方向、一次受挫后可补救”。避免所有流派最后只换了发光颜色，实际仍是同一套循环。

### 7.5 敌人与 Boss：少种类，多组合

- 现有 8 类敌人与 4 个 Boss 为内容基底；先规范职责、主形、启动信号、攻击边界、恢复窗口和音效。
- 追击、远射、冲撞、区域封锁、支援等职责形成组合；避免全部追着玩家堆数值或所有敌人同一时刻发动。
- 组合必须有至少一种基础移动/冲刺即可应对的窗口，不能要求尚未获得的祝福才能生存。
- 前摇在接近危险时仍可辨，攻击区域与实际判定一致；不靠更大的 Bloom 或小字号倒计时补救不合理前摇。
- Boss 每阶段用少量招式建立、考验已有知识；血量阶段变化改变组合与节奏，不默认大量召唤和全屏特效。
- 战斗反馈按普通/暴击/破层/击杀/受伤分级，普通高频事件最克制；hit-stop、屏震、光雾和声音不全拉满。
- 减少屏震、降低发光、开最低性能档时，核心信息和挑战仍成立。

### 7.6 房间、事件与局内经济

- 在已有房型上先做空间变体：狭长通道、开放反应区、分隔障碍、局部反射板、有限危险区；每种都核对路径可达和视觉/碰撞同源。
- 入口提示奖励大类、风险和必要代价；未知可以是收益细节，不是未提示的永久损失。
- 事件保持“一句氛围＋明确选项＋代价/结果提示”，长背景在二级展开；总有可离开的保底选项。
- 事件建立结果标签和后续呼应，以已有12个事件做少量连锁，优先深度而非随机拼更多标题。
- 商店4格基础维持；价格取5的倍数只是心算工具，是否值得买由房均收入、保底补给与实际强度决定。
- 明确“券＝局内购买/投资资源，样本＝撤离带出成长资源”；不把多个进度计数都当第三种货币。
- 投资分为累计进度与可用余额：若设计不提供取款，明确为研究投入而非宣称完整复刻IS银行；若提供取款，要有明示额度/时机与防刷规则。
- 分别验证买补给、买构筑、投资、提前撤离的机会成本；死亡不兑现券仍可保留探索记录/新信息，不用免费返还大量财富消灭撤离风险。
- 经济测试覆盖零券、满库存、投资满额、旧存档、重复结算与事件卖物，避免文案和资产不同步。

### 7.7 难度与氛围

- 标准难度优先“首局能学到并到达一个明确目标”，不要求未养成的新玩家立即通关；经验玩家的熟练度应带来明显改善。
- 辅助模式可增加预警可见时间、输入宽容或容错；不自动代打，也不偷偷改变标准难度。参数和成就影响需清楚说明。
- 高难通过玩家主动选择的挑战词缀/房型/资源压力扩展，而非隐藏加速、敌人无限血量或不可见招式。
- 局外优先横向解锁，纵向数值成长设可控上限；强度需要设计预算，不能无限乘区堆出必刷养成。
- 环境故事用终端、实验残留、光照和短语音/音效建立，不到处堆公式或强制长对话。
- BGM/环境音随探索、战斗、精英、撤离改变；密集危险时收环境光/雾和低价值音，使空间与风险更清楚。
- 化学比喻需一致，但不假装是严谨化学模拟；技能文案优先告诉玩家“会发生什么”。

## 8. 拟定工程边界与迁移方式

不在本次创建下述代码目录。未来建议围绕现有工程逐步形成：

```text
src/game/visual/
  styleTokens / materialCatalog / renderProfile
  RenderDirector / GlowComposer / ReflectionComposer / OcclusionComposer
src/game/fx/
  FxDirector / ParticleField / FxBudget / EffectCatalog
src/game/perf/
  PerfRecorder / CapabilityProbe / FrameBudgetController
src/ui/
  bridge/UiSnapshot / UiCommands / PauseCoordinator / InputRouter
  components/ HUD / Panel / ChoiceCard / Navigation / TouchHints
  styles/ tokens / material / motion / layouts
assets/
  fonts / icons / atlases / materialMasks
tests/ 与 scripts/
  状态对账、输入事务、布局回归、确定种子压力场景、帧时间报告
```

- GameScene 保留权威战斗流程，Render/Fx只消费只读状态或语义事件。
- 表现事件包含实体ID、事件ID、位置/高度、方向、强度和重要性；无论画质如何，事件源保持一致。
- 质量设置集中成一个源；避免 SettingsState、visual/quality、utils/Quality 与多个 UI 开关互相打架。
- 游戏级表现服务与场景资源所有权分开；Scene shutdown 销毁本场景目标/监听，不销毁其他场景共用资源。
- 房间缓存、RT、字体图集和粒子池有明确的 acquire/release/resize 生命周期；换房/旋转不遗留旧纹理。
- DEV-only 测试契约暴露真实实例、可控seed与场景状态；测试走正常Boot，不动态导入另一个状态实例、不在 iframe 中验证 WebGL。

## 10. 验收矩阵

### 10.1 美术与特效

- [ ] 一张风格板包含主形、允许/禁止例、线宽、配色、材质族、光芯/辉光与UI组件。
- [ ] 小屏实际大小下，单主形、圆/棱角、明暗/遮挡与角色职责可辨。
- [ ] 地面菱形、不阻挡装饰、阻挡侧壁与碰撞数据一致。
- [ ] 微粒边缘完全透明，无矩形裁边；密度聚散和局部扰动在视频中可见，不只比较静态截图。
- [ ] 反射脚点/遮挡/模糊、AO与受光方向一致；近似与真实算法分别记录。
- [ ] 强Bloom混战、灰度/色觉模拟、减少闪光设置下仍能看见玩家、敌人意图和安全路径。
- [ ] 静图＋有声连续录屏＋正常速度人工审阅，不能以像素采样取代观感/听辨。

### 10.2 性能场景

同一录制/seed进行旧版、优化版和不同档位 A/B，记录数量/分辨率/renderer，不使用无限无效生成代替真实峰值：

1. 完整Boot、字体/音频就绪、首次入场与首次攻击。
2. 房间切换、首个新怪/Boss/shader、奖励、商店、事件和祝福首次打开。
3. 合法最高敌人/弹道/电子密度，连续近战、远程、击杀连锁和染料特效。
4. 大面积辉光＋反射＋AO＋雾同开；玩家危险提示与UI仍在。
5. 撤离倒计时、Boss阶段切换、死亡结算、连续重开10次。
6. UI快速开关/滚动/页签/长文、画质切换、窗口resize/旋转、失焦/恢复。
7. 30分钟热状态完整游玩，确认池/纹理/监听不增长。

首次加载独立报告启动耗时，但首次交战、换房和菜单不豁免。截图/录屏与性能采样可分轮避免采集工具干扰，方法必须注明；运行时读回像素不属于性能基准热路径。

### 10.3 UI 与设备

- PC：1280×720、1366×768、1920×1080、4:3；100%/125%/150%缩放与不同DPR。
- 移动端实际CSS视口：640×360（16:9）、800×360/960×432（20:9）、844×390、安全区；360×800竖屏，320×568紧凑压力测试。
- 最大文字长度、较大字体、中文缺字/字体慢加载、空状态/满库存/长属性说明。
- 鼠标、键盘、双指/多指、pointercancel、返回键、暂停叠加、触摸退出；移动端不能以桌面点击模拟就宣称通过。
- 自动矩形检测覆盖静态和动画峰值：出屏、关键控件相交、按钮被面板/手指区挡住；再人工检查可读性与操作路径。

### 10.4 玩法与平衡

- 状态接线：UI显示和实际生命、伤害、暴击、温度、装备/染料、遗物套装、投资解锁一致。
- 多seed无不可达路线、无无解事件、无强制依赖稀有祝福的基础局；性能档不改变模拟结果。
- 同等装备/进度下比较三条流派的可完成度、耗时、承伤、热压和收益，不能直接用全玩家混合胜率决定削弱。
- 起始目标：主要可玩流派效率不低于同条件最佳者约70%，不靠一套构筑压倒所有选择；具体阈值经样本评审再锁定。
- 新手/熟练各安排至少5位真实试玩者作为第一轮小样，记录操作错误、解释不出的死亡、退出原因和下一局意愿；小样不能宣称统计定论。
- 观察关键选择分布、补救成功、提前撤离价值、投资机会成本、房间疲劳和复玩差异；问“死因是否明白、改进是否可做”，不只问“好不好玩”。

## 11. 暂不采用与风险清单

### 11.1 暂不采用（保留理由，不静默丢弃需求）

- **默认全屏真实SSR＋SSAO＋TAA＋高步数体积雾叠满**：当前缺辅助数据且HD4400成本未知；先纵切逐项测。
- **为“PBR”迁移完整3D引擎**：超出请求与现有架构范围；更换引擎不自动解决性能或UI。
- **所有主体改厚外壳/所有图形变不对称**：与新风格冲突，且无必要功能依据。
- **把粒子换成大片贴图、固定环扩散**：与逸散云雾要求冲突；保留关键机制圆环属于信息例外。
- **以少刷怪、改判定、降模拟速度换帧率**：不同画质不应成为不同游戏。
- **所有UI每帧重新渲染、每个面板持续背景模糊**：先有准确成本再决定；CSS并不天然比Graphics快。
- **批量新增几十个武器/事件/遗物**：先让现有机制真的工作并有可玩组合，不用数量证明耐玩。

### 11.2 主要风险与应对

| 风险 | 应对 |
|---|---|
| HD4400实际环境未可测 | P0阻止“已达60帧”结论；不拿独显/远程/软件限速替代 |
| 风格目标与真实算法预算冲突 | 目标观感、近似路径、真实算法分别列证据；必须更改要求时回到审阅，不偷换 |
| 高Bloom/软雾掩盖战斗 | 固定危险信息层、曝光和屏幕覆盖预算，灰度与最差场景测试 |
| UI混合造成重复输入/暂停错误 | 单命令入口、事务去重、暂停token、穿透/多指/重开回归 |
| 缓存/池化导致内存增长 | 所有权和容量上限、resize与shutdown审计、10次重开与30分钟测试 |
| 平衡修改损坏旧成长/存档 | 接线对账、存档迁移、数值变更说明、同seed分批A/B |
| 字体/音画来自参考商业资源 | 来源与许可审核，本地自制或可分发替代，未闭环不得标可发布 |
