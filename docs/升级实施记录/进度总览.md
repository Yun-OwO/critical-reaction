不是时间或意愿问题，而是这些工单存在**我无法自行解除的阻塞**。继续写代码只会产出一批
无法判定通过与否的改动，比停在这里更糟：

### 1. 视觉验收必须由你做

规格 §I 把「用户审阅连续观感」设为 P1→P2 的**硬门槛**：风格板、主形/线宽/配色、
明暗面与排线、菱形投影是否成立、软雾是否像流体云雾而非一团光——这些判断的标准在你
手里，不在代码里。我可以按参数生成资产，但「精准干净、矢量图感、高级感」这类验收
只能由你看着画面判定。我自己截图再自己宣布通过，等于把验收标准降级成自查。

### 2. T10 的核心目标无法在本机验证

HD 4400 稳定 60 帧是 R14。当前浏览器实际渲染在 NVIDIA P104-100 上。T10 的优化
（批次、缓存、上传预热、过绘制）在独显上跑出来的数字，对集显没有参考价值——
瓶颈位置可能完全不同（集显的填充率与带宽压力远大于独显）。你已说暂时忽略核显调用，
那我只能做到「实现优化手段 + 测量工具就绪」，**不能**声称 60 帧达标。

### 3. T15/T17 需要真人试玩

规格要求新手与熟练玩家各至少 5 位，记录死亡原因是否可解释、是否愿意再开。我不是
试玩者，无法代替。构筑是否耐玩、门槛是否合适，只能由真实玩家回答。

### 4. T12/T13 的 UI 动效需要真机与真人

移动端触摸、safe-area、返回键、多指、实际 20:9 视口，以及「丝滑不跳帧」的观感，
桌面模拟点击无法代替。多指与外放行为尤其如此。
