## 2. 关键审计发现

### 2.1 本作世界坐标系是「屏幕平面」，不是 3D

`GameScene` 的世界是一张 **4800×2400 的屏幕平面**：

```
src/game/scenes/GameScene.ts:275  worldWidth = 4800
src/game/scenes/GameScene.ts:276  worldHeight = 2400
```

角色、地形、道具都直接用屏幕 x/y 移动；障碍的“高度”只在绘制时把顶面菱形
往上平移（`GameScene.ts:7626`，`y - h/2 - lift`）。`projectXZ()` 里的
`z` 只用于视差装饰与大厅网格，**不是实体的真实空间坐标**。

**因此**：

- 直接拿屏幕 Y 当深度是错的（它同时混了 z 与 height）；
- 拿 Phaser 的 `depth`（`depthFromXZ()`，含图层常量如 80/98/100）当深度更错；
- SSR 的辅助深度缓冲必须自己生成，不能复用引擎排序值。

### 2.2 现有等距投影的真实形式

```
GameScene.ts:1346   projectXZ({x, z}, { axisX: 1, axisZ: 0.52, depthScale: 0.00002 })
LobbyScene.ts:168   projectXZ({x, z}, { axisX: 1, axisZ: 0.52, depthScale: 0.00002 })
projection.ts:34    x = originX + x·axisX + z·axisZ
projection.ts:35    y = originY + z·0.5
```

即屏幕投影是 2×3 正交投影。零空间方向（相机前向轴）由

```
axisX·fx + axisZ·fy = 0,  axisY·fy + heightCoef·fz = 0
```

解出。本作参数下：

| 量 | 值 |
|---|---|
| forward（零空间方向，已归一） | `(-0.42172, 0.81100, 0.40550)` |
| alpha / beta | `1.1271202` / `0` |
| gamma / delta | `0.2306764` / `-1.0939783` |

`beta = 0` 说明屏幕 x 只由 vx 决定（z 方向在屏幕上不产生 x 位移的视图分量），
这是 `axisZ` 已被吸收进 `alpha` 的结果，符合预期。

### 2.3 战斗 RNG 污染在表现热路径（规格 D 章节预告的问题确实存在）

`GameScene.ts` 中纯表现用途仍在消耗战斗 `this.rng`：

| 位置 | 用途 | 是否纯表现 |
|---|---|---|
| `4976` `this.rng.between(90, 180)` | 旋风斩火花寿命 | 是 |
| `5028` `this.rng.between(140, 240)` | 刀尖余烬寿命 | 是 |
| `6584` `Math.sin(performance.now() * 0.02)` | 炸弹闪烁 | 是（非随机，但用挂钟驱动） |

**影响**：同一 seed 下，玩家是否开启/关闭这些装饰会改变后续战斗随机序列。
这违反执行规格「画质开关不改变模拟结果」。T02 需引入独立 `FxRng` 并迁移这些调用点，
迁移后旧基线不再逐位一致，需重新固定基线并验证「画质/静音/VFX 开关不同但模拟一致」。

## 3. 实现要点

### 3.1 为什么用「正交相机」而不是「高度场近似」

规格 §E2 要求真实 SSR 射线求交，且明确禁止用整屏上下翻转代替。2×3 正交投影
的零空间方向是**解析可解**的：由此得到的前向轴是一个真实的正交相机轴，
配合其导出的正交 right/up 基，就得到深度为 `dot(p, forward)` 的完整视图空间。
这满足 SSR 求交所需的三个性质：

1. 世界 → 视图 → 屏幕与现有屏幕公式**逐点等价**（不会与实际绘制错位）；
2. 深度能区分「同屏幕位置但被抬高的表面」（AO / 反射才有意义）；
3. 视图空间 ↔ 世界唯一可逆（射线求交有确定解）。

### 3.2 一个实现中发现的真实错误（已修正）

`unprojectToGround()` 初版写成 `vd = height / forward.z`。这**漏掉了视平面自身的
高度贡献**：

```
height(p) = vx·right.z + vy·up.z + vd·forward.z
```

`right.z` / `up.z` 一般不为 0，所以必须先减去平面项再解 `vd`。
初版在 `height=16/48/96` 时无法把点还原到请求的高度上，被单测抓到后修正。
这条错误正是 T01 存在的意义：T06 若在错误前提下实现 SSR，后续所有反射都是错的。

### 3.3 一处测试期望写错（非代码错误）

「离屏立即返回」用例原用 `u0=0.98, stepScale=0.02`，此时第 1 步 `u = 1.00`
仍算在屏幕内，第 2 步才越界。已改为 `u0=0.99`。**这是测试写错，不是实现偏差**，
如实记录以免后来者误以为改过离屏判定。
